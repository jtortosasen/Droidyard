## The difference that decides what transfers

Orca owns the agent process: it launches each CLI in a pty it hosts, injects identity into its
environment (`ORCA_PANE_KEY`, `ORCA_WORKTREE_ID`, a launch token, a hook token and port), reads
its terminal, types into it and restarts it [read]. Droidyard owns the toolchain and a typed
contract, and sees agents only through their MCP connection and the hooks `init` writes
(ADR-0004: no in-house harness). What transfers is the observable half of Orca (agent state,
attention signals, status lines, history, inventories, review notes, pairing UX); what needs
control of the agent does not (launching, prompting, hibernating, orchestrating, "Fix with AI").

## Corrections to the first, quick reports

- Pairing: the direct pairing link is a 192-bit bearer token with no expiry and not single use,
  though Orca's docs say "one-time" and "expires in minutes"; only the relay invite is single
  use (10 min, 5 attempts) [read, remote §2.3].
- Per-line attribution is documented and not found in the code [read, worktrees §3.2].
- Review notes are pushed: pasted into the agent's terminal and deleted when delivered (the
  docs say they stay pinned); there is no pull channel [read, worktrees §3.1].
- Orca does not install Claude Code's `Notification` event; it uses `PermissionRequest` and an
  `AskUserQuestion` PreToolUse for "waiting" [read, agents §1.2].
- "Cursor's permission hooks fail closed on empty stdout" is Orca's claim, not Cursor's docs
  [read, agents §6]. Droidyard's spike saw the opposite in `cursor-agent` 2026.10.16 `-p`: the
  recorder printed nothing on allowed events and the writes and commands went through [obs,
  [spike-c2-occupation](spike-c2-occupation-2026-10.md) (e), run e1]. The IDE is not measured.
  Orca answers `{"permission":"allow"}`, which would also bypass Cursor's own approvals:
  Droidyard keeps `{}`.

## What Droidyard already does better, and keeps

- Devices, by a wide margin: Orca's Android backend is a thin adb wrapper beside its iOS
  simulator (comparison below). Two of its worktrees can drive one emulator with no check;
  Droidyard's occupation (ADR-0094) refuses that.
- A typed contract (`schema/capabilities.json`, structured errors, the tool-list budget)
  against Orca's text guides ("do not invent flags from memory") [read].
- Security posture: Orca launches agents with `--dangerously-skip-permissions`, `--yolo`,
  `--dangerously-bypass-approvals-and-sandbox` by default ("the worktree itself is the
  sandbox") and pre-writes the clients' folder-trust markers [read]. Droidyard's policy is
  changed by the person only (ADR-0015), shell is off by default, device text is untrusted.
- Remote: lane 2t's pinned mutual TLS, hand pairing, IP-literal bind, `Origin` refusal,
  2-second revocation and per-peer audit avoid Orca's shared bearer link, `0.0.0.0` bind,
  plain `ws://` under a home-made E2EE, UI-only revocation and missing audit [read, remote §6].
- Lean: one Go binary against about 5M lines of TypeScript on Electron and node-pty [read].
- Activity covers both consumers and restores deletes (ADR-0096); Orca's feed lists agent
  events only, 5 per pane and 80 in all [read].
- Per-project hook entries rather than Orca's global user-level ones: no stale copy in other
  projects, nothing installed outside the project the person chose.

## Not to copy

- Agents launched with approvals and sandboxes disabled, and pre-written folder trust.
- Hosting and orchestrating agents (runs, tasks, dispatch, inbox, decision gates, "Generate /
  Fix / Resolve with AI", scheduled automations): a harness (ADR-0004). For a blocking question
  MCP elicitation is the standard route.
- Global user-level hook installation, the managed `CODEX_HOME` mirror and Codex's hook-trust
  hash writer (they exist to make global hooks work).
- OSC 7501: only the terminal host can read it [read and doc, agents §3].
- Electron, the bundled browser, the native phone app, telemetry on by default, issue-tracker
  boards, account usage tracking.

## Android: Orca against Droidyard

| Capability | Orca [read] | Droidyard |
| --- | --- | --- |
| Emulators | list, boot by `attach` (blind 180 s poll), `emu kill`; no wipe, no AVD create | adopt-first boot, owned until its serial, stop, wipe |
| Physical devices | listed, no gate; `shutdown` would `emu kill` a phone | hidden unless allowed and allowlisted, re-checked per call |
| Install, launch | `adb install -r <apk>`; launch with no pid or crash check | build-referenced install, launch with pid, crash on actions |
| Logs | one-shot `logcat -d` dump | snapshot and follow, by app, crash buffer |
| Screenshot | none for the agent | `device.screenshot` |
| Live view | scrcpy, server jar downloaded with a size check only | scrcpy, pinned and hashed server |
| Input | `adb shell input`; a gesture reduced to its end points; ASCII text | tree selectors, act-and-assert, swipe paths |
| UI tree | `uiautomator dump`, raw bounds | persistent reader, selectors |
| Build | none | `build.*` with structured errors |
| Concurrency | an active device per worktree, shared without a check | occupation (ADR-0094) |
| Agent surface | CLI and a skill, no MCP; no untrusted marking, `exec` runs any shell | capability API over MCP, untrusted text marked |
| Ahead of Droidyard | iOS simulator; Linux and Windows device control claimed | — |

Worth noting only: an `exec`-style escape behind the policy fence if a real need appears; a
per-backend capability set if iOS ever comes; a skill stub that loads a version-matched guide.
