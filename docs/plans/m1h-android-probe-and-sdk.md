## Delegated decisions

Taken under the owner's standing instruction; each can be reverted.

- D1. **Scope: `sdk.status` and `sdk.requirements` are in.** Without `sdk.requirements` the probe's `compileSdk`, build-tools and SDK directory have no consumer (fields read for nothing prove nothing); `sdk.md` §Capabilities calls it "the one to build first"; both are pure Go over `package.xml` and need no JVM beyond the model fetch; `sdk.requirements` needs the host SDK for `sameAsHost`, which is all `sdk.status` publishes. The rest of Phase 1 is deferred per §Scope.
- D2. **S3 in two parts.** Part 1 (step 1) runs before any probe code: a scratch Groovy init script calling the same public DSL the probe will (a spike instrument, not the product, which ADR-0023 §Alternatives considered requires to be a jar), on four cells, so step 2's Java is written against observed getters. Part 2 (step 2, main session) measures the real probe's cost and fields on DopamineControl. Findings that alter a later step are recorded under Changes before it starts.
- D3. **Fixture** `sidecar/testdata/flavoured/`, Groovy DSL, pinned to DopamineControl's cell: wrapper `distributionUrl` Gradle 8.13; `settings.gradle` `pluginManagement` with `com.android.application`/`com.android.library` 8.13.2 and `org.jetbrains.kotlin.android` 2.0.21; `gradle.properties` with `android.builder.sdkDownload=false` (S7), `org.gradle.daemon.idletimeout=60000`, `android.useAndroidX=false`; no wrapper jar and no `local.properties` (as `plain`; tests and runs add one naming the host SDK). `:app`: application `dev.droidyard.flavoured`, `compileSdk 36`, `buildToolsVersion "35.0.0"`, `minSdk 24`, dimensions `tier` {`free`, `paid`} and `stage` {`staging`, `prod`} with `applicationIdSuffix` each, build types debug and release (eight variants, `paidStagingDebug` …), one Java `Activity` (no AndroidX) whose only view shows `getPackageName()` and a string from `:lib`. `:lib`: Android library with one Kotlin file, no flavours. Step 2's test rewrites the versions per cell in its temporary copy: C1 as pinned; C2 Gradle 9.6.0 and the newest AGP 9.x that runs on it (chosen and recorded by step 1), the Kotlin plugin lines removed (AGP 9's built-in Kotlin); C4 AGP 8.0.2 on Gradle 8.0.2, its `distributionUrl` a `file://` URL to the zip `build.sh` fetched for D4, so the floor row of ADR-0018 §Consequences runs whenever that build cache exists (skipped, naming it, otherwise).
- D4. **Probe packaging.** Java sources in `sidecar/probe/src/`, compiled by `sidecar/build.sh` with `javac --release 8` against Gradle 8.0.2's distribution `lib/` jars only, its own Tooling API jar included (the floor's public API, ADR-0023 §Decision 2, so neither the probe nor the `BuildAction` can call what an 8.0 daemon lacks; the distribution fetched with its SHA-256 pinned, into the build cache), into a third jar `sidecar/jars/droidyard-probe.jar` (sorted entries, fixed timestamps); the `javac` version recorded beside the digests and the reproducibility test skipping, naming both, on another `javac` (the m1g D4 rule). The init script `sidecar/probe/droidyard-probe.init.gradle` is fixed text that puts `new File(initscript.sourceFile.parentFile, 'droidyard-probe.jar')` on its classpath and applies the probe's `Plugin<Gradle>`; both are embedded in `sidecar/sidecar.go` with pinned digests and written by the core into `<cache>/gradle/probe-<digest>/`, atomically, rewritten when different (m1g D5). `Amended:` lines on ADR-0017 (the third jar, `javac`) and ADR-0021 (the probe's directory in the cache), by the main session with step 2.
- D5. **One `BuildAction`** (ADR-0023 §Decision 1) in the probe jar returns the `GradleProject` tree and, per project, the probe's model through `findModel`, each project's `findModel` in its own `try` (a throwing project is omitted from the probe data, noted, `partial`). `project.model {root, probe}`: with `probe: true` the sidecar passes `--init-script <path>` to that action only. The action lives in its own package, `droidyard.probeaction`, and asks for `GradleProject` first, outside any `try`, so a project's own configuration failure surfaces there. **Retry only when the probe is to blame**: if the action fails and the failure chain names the init script's file or has a frame in a class of the package `droidyard.probe` (the plugins, the model builder, the variant callback; never the action's package), it is run once more without the probe, and the reply is the generic model with `probe.status: failed` and the first failure's message as a note; if that retry fails, `PROJECT_MODEL_FAILED` with its failure. Any other failure (the project's own configuration is broken) fails `PROJECT_MODEL_FAILED` at once, one pass, as in 1g; a cancelled fetch is never retried. A failed fetch's reply carries the failure chain's messages, de-duplicated, each cut at 8 KiB, at most 20 (m1g D6's bounds), so the core's `PROJECT_MODEL_FAILED` cause holds the nested Gradle and AGP text, not only the Tooling API's wrapper (today `Session.kt` sends `e.message` alone). `probe: false` → `probe.status: skipped`. The core always sends `probe: true` (no configuration key exists to turn it off). `Amended:` line on ADR-0023 with step 2.
- D6. **Fields the probe reads** — only those with a consumer here: AGP version, KGP version (AGP 9's built-in Kotlin included, from wherever step 1 finds it), per Android project the compile target string, the effective build-tools version, the SDK directory AGP resolved, and the variants `{name, buildType, flavors [{dimension, name}]}` (dimension order) from `androidComponents.onVariants`, registered when the Android plugin is applied. Not read: `namespace`, `minSdk`, module type, `kotlinBuiltIn` (no consumer; ADR-0023 §Decision 2 gets an `Amended:` line naming them as deferred, with step 2; `gradle.md` §The probe and §Version detection and toolchain profile item 3 are reconciled at the close). **A departure: the owner should see it.** Each read sits in its own `try`/`catch (Throwable)`: a failure omits the field and adds a note `"<project path>: <field>: <exception class>: <message>"` (at most 50 notes, each cut at 512 characters); `probe.status` is `ok` when every field of every Android project was read, `partial` otherwise. AGP and KGP are build-wide: the first project in path order that reports one; a different value elsewhere adds a note; none → `"unknown"`. The init script logs one lifecycle line, `droidyard-probe: applied` (D17).
- D7. **Protocol 2.** `hello` reports `protocolVersion: 2` and the client refuses anything else (`gradle.md` §Protocol: matched pair). The sidecar's launch classpath gains the probe jar; the init script's path is given at launch as `-Ddroidyard.probe.init=<path>`. The reply keeps `projects[]` and adds `plugins {agp, kgp}`, per project `android? {compileTarget?, buildTools?, variants[]?}` (`sdkDir` too, core-internal) and `probe {status, notes[]}`.
- D8. **`project.variants` additive.** `variants` (names) unchanged; each module gains `details[] {name, buildType, flavors [{dimension, name}]}` when its `source` is `probe`. Per module: `source: probe`, `exact: true` when the probe read that project's variants (a non-Android project with the probe `ok` → `[]`, `probe`), otherwise the task-name fallback as today. Changing `variants` to objects would be a breaking change (`capability-api.md` §Discovery and versioning).
- D9. **One variant source for every consumer**: `build.assemble`'s validation and `resolveOutputs`' `package<Variant>` mapping use the same per-module function D8 publishes, so a flavoured module's outputs and validation follow the exact variants. A library's probe variants make `build.assemble {":lib", "debug"}` valid: it builds the AAR and reports no `outputs` (no `package<Variant>` task, ADR-0023 §Decision 6); `project.variants`' description says so instead of "a library reports an empty list".
- D10. **The toolchain profile in build results** (ADR-0018 rule 1, rule 6; ADR-0022 §Decision 3): `agp` and `kgp` from the model the build ran with (`dispatch` already fetches it), `"unknown"` when the probe did not read them; and `expectedSources {kotlin, javac, aapt2, manifestMerger, ksp, kapt}`, each `problems` or `console`, by `gradle.md` §Version detection and toolchain profile item 4: Kotlin `problems` when the connection has `problemLocations` and KGP ≥ 2.4 (an unknown KGP is below), javac `problems` with `problemLocations`, the other four `console`. A pure function of the connection's capabilities and the plugin facts; it reports, it never switches the extractor off. Persisted with the record.
- D11. **`sdk.status`** `{found, root?, source?, rejected [{candidate, source, reason}], warnings[], installed {platforms[], buildTools[], platformTools?, cmdlineTools[], emulator?, systemImages[]}}`, each package `{id, version}` (`id` the `package.xml` `path`); no availability requirement and no new code: with no host SDK it answers `found: false` with every candidate rejected and the variable that would fix it. `capability.RequiresSDK` stays unused (reported missing, as today) until `emulator.*` needs it. Not here: `licenses`, `deviceProfiles` (their consumers, `sdk.licenses` and `emulator.create`, are post-MVP), the `sdk.root` key (no configuration specification; m1e R5), an SDK block in `system.health` (`sdk.status` answers it). **A departure: the owner should see it.**
- D12. **`sdk.requirements`** (no parameters) `{source: probe | failure-signatures, complete, projectSdk {found, root?, source: agp | local.properties | env, exact, sameAsHost}, hostSdk {found, root?}, required [{module, package, installed}], missing [], notes[]}`; a note names `sdkmanager --sdk_root=<projectSdk.root> "<package>"` for each missing one, which is why the project SDK's root is published here (the SDK to install into; `gradle.md` §Project model's "core-internal" means "not in `project.*`", reconciled at the close). Project SDK per `sdk.md` §Project SDK: the probe's directory (`agp`, exact), else `local.properties` `sdk.dir` (Java properties escapes; relative to the root), else `ANDROID_HOME`, `ANDROID_SDK_ROOT` from the daemon's environment (`exact: false`); none → `found: false` and the note that the build will fail with "SDK location not found". `required` per Android module: `platforms;<compile target>` (matched as `sdk.md` §Reading what is installed says, by step 1's G4) and `build-tools;<version>`. `complete: false` when any Android module lacks a field. **A missing platform is answered on both branches of step 1's G6**: if a configuration pass survives it, the probe's compile target puts it in `missing` (`source: probe`); if it does not, the model fetch fails `PROJECT_MODEL_FAILED`, and `sdk.requirements` passes that failure's cause (D5: the chain's messages) to the console extractor's first "AGP SDK" form, AGP's missing platform, and answers `source: failure-signatures`, `complete: false`, `missing: ["platforms;android-N"]` instead of failing; an unrecognised configuration failure stays `PROJECT_MODEL_FAILED`. The form lives in `internal/domain/build/extract`, the one parsing component (ADR-0022 §Decision 2, §Decision 6), with a golden test over the text **as the sidecar delivers it** (recorded at step 2's level 4), and is built only if G6 found a configuration pass failing on C1 or C2; if it survives on both, the probe branch alone answers and no matcher is written (recorded under Changes). `category: sdk.missing` records in `build.errors` stay deferred. Without the probe and without a recognised failure: `source: failure-signatures`, `complete: false`, `required: []`, and a note. Other AGP SDK signatures (licences, build-tools) wait for their recordings (`gradle.md` §Console extractor, row "AGP SDK"). **A departure: the owner should see it.**
- D13. **Host-SDK discovery** moves from `internal/domain/device/resolve.go` to `internal/domain/sdk` (`Host(env)`), called by adb resolution with unchanged behaviour (m1e's `TestResolveOrder` unchanged and green).
- D14. **`package.xml` walk**: fixed relative locations (`platforms/*`, `build-tools/*`, `platform-tools`, `cmdline-tools/*`, `emulator`, `system-images/*/*/*`), at most 2 000 files of at most 1 MiB each, a malformed one skipped with a note; no `sdkmanager`, no JVM (`sdk.md` §Reading what is installed). Read fresh on every call; the model stays cached.
- D15. **Real-Gradle tests are opt-in** (`DROIDYARD_GRADLE_TESTS=1`, m1g D14) and skip naming the level they would reach; the host SDK is located by D13 and the test skips when there is none.
- D16. **The fake sidecar stays stateful** (m1g step 5 lesson): `gradletest` answers `project.model` with probe fields only for `probe: true`, per connection, and has a mode for each `probe.status`.
- D17. **"Never in a build" is checked by its marker**: the init script's lifecycle line must appear when it runs (step 1, G9, on the command line: a probed fetch's output is not forwarded, so this is the only positive control, and a later Gradle that dropped init-script lifecycle lines would make the negative check vacuous) and never in a build's console after a probed model fetch (step 2).
