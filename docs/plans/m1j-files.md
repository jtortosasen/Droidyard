## Delegated decisions

Taken under the owner's standing instruction; each can be reverted.

- D1. **Scope: `file.*` only; `policy.*` and `shell.exec` in 1k.** They need the configuration specification (policy keys, device rules, `shell.exec` global and per workspace, how `droidyard trust` relates to `policy.update`), which is design, not planning: an ADR, or an amendment to ADR-0031, must exist before the 1k plan, or that plan is `Blocked` on it. Writing that ADR can run beside 1j's implementation, which needs none of it. Joined with 1j the milestone would pass ten steps and mix a security-sensitive authorization change with an unrelated domain.
- D2. **Paths.** `path` is relative to the workspace root, slash-separated; `""` and `"."` are the root. An absolute path is accepted only when it lies lexically under the canonical root `workspace.describe` reports (at a component boundary), and is then made relative; any other absolute path is `FILE_OUTSIDE_ROOT`. A path that `filepath.IsLocal` rejects after cleaning (it climbs out with `..`) is `FILE_OUTSIDE_ROOT`; a NUL byte, or `""` where a file is required, is `REQUEST_INVALID_PARAMS`. **Containment is enforced by `os.Root`** opened on the canonical root for each call: every open, stat, mkdir and rename goes through it, so a symlink (relative or absolute, final or intermediate) or a `..` that resolves outside the root fails inside the kernel walk, with no check-then-open race. The lexical check only chooses the code early; when `os.Root` refuses an escape the lexical check missed (a symlink), the handler confirms it with `filepath.EvalSymlinks` to report `FILE_OUTSIDE_ROOT` rather than `FILE_IO_FAILED`. Symlinks inside the root are followed for reads. Results echo the cleaned relative path as the caller wrote it (on a case-insensitive volume, `SRC/a.kt` reads `src/a.kt` and is echoed as given).
- D3. **Codes.** `FILE_NOT_FOUND` (nextStep: `file.list` the parent), `FILE_OUTSIDE_ROOT` (`details {path, root}`; nextStep: "pass a path inside the project root; files outside it are not reachable through droidyard"), `FILE_WRONG_TYPE` (a directory where a file is needed or the reverse, a FIFO, socket or device, a write to a symlink or over a file without its owner-write bit; `details {path, type}`), `FILE_IO_FAILED` (permission, no space, any other I/O error; `cause` the OS error). Not found, not a directory and unreadable are not split further (the ADR-0026 reasoning: the consumer's reaction is the same and `cause` says which). Each descriptor lists only the codes its handler returns (1i lesson); `WORKSPACE_NOT_OPEN` comes from `Start` and is not listed.
- D4. **`file.list {path?, limit?}`** → `{path, entries [{name, type: file | dir | symlink | other, size?, modTime}], truncated, hint?}`: one directory level, never recursive; symlinks reported as `symlink`, not followed; names sorted bytewise; `limit` 1–2000, default 500. The directory is read in chunks and reading stops at 20 000 names (the cap while capturing, `capability-api.md` §Bounded output); `truncated` when more names exist than are returned, with the hint "list a subdirectory". An empty directory is `entries: []`.
- D5. **`file.read {path, offset?, limit?}`** → `{path, size, modTime, offset, nextOffset, text?, truncated, binary}` with ADR-0012 §Reading artifacts' paging exactly (default 16 KiB, max 256 KiB, negative offset from the end moved to the next line start, the last complete line, a longer line cut at a UTF-8 boundary). `artifact`'s paging is refactored to read from an already open `io.ReaderAt` plus a size, so `file.read` pages the descriptor `os.Root` opened and never reopens by name; `artifact.read` keeps its behaviour (its tests unchanged). Regular files only: opened `O_RDONLY|O_NONBLOCK` and `fstat`ed, so a FIFO is `FILE_WRONG_TYPE` at once instead of blocking the handler. `binary: true` when the window holds a NUL byte or invalid UTF-8 (a rune cut by the window's end excepted); then `text` is omitted and `size` still says how large the file is.
- D6. **`file.write {path, content}`** → `{path, size, created}`. `content` is UTF-8 text of at most 512 KiB (else `REQUEST_INVALID_PARAMS`), so a request stays under the 1 MiB HTTP and WebSocket bound after JSON escaping in ordinary text. Missing parent directories are created (`Root.MkdirAll`, 0755 before umask). The write is atomic by ADR-0021 §Format's recipe applied to a project file: a temporary `.<name>.droidyard-<8 hex>.tmp` created `O_EXCL` in the target's directory, written, `fsync`ed, given the existing file's permission bits (0644 before umask for a new file), renamed over the target, then the directory `fsync`ed; every failure path removes the temporary file. Refused with `FILE_WRONG_TYPE`: a target that is a directory or a symlink (a rename would replace the link, not write its target), a parent component that is a file, and an existing file without its owner-write bit (a rename would silently defeat the read-only mark). A rename gives the path a new inode: a hard link to the old file keeps the old content (said in the description). **A daemon killed between the temporary file and the rename leaves that file in the project**: ADR-0021 keeps state out of the project, and this is a transient file, not state; it is named so a human recognises it, and `file.watch` ignores the pattern. Works on an untrusted root (ADR-0015 §5).
- D7. **`file.watch {path?}`** → `{subscriptionId, watched, truncated, excluded []}`. A **command**, as `events.subscribe` is (it creates a subscription; a query that writes is a `Kind` bug, `mcp-tool-surface.md` §Annotations), which settles `capability-api.md`'s "Q (to revisit)"; `Streaming`, so only the WebSocket session may call it (ADR-0010). **The watcher polls**: before returning, the handler walks the watched directory through `os.Root`'s `FS()` (symlinks not followed) and records each entry's type, size and modification time; then a goroutine walks again every second and publishes the differences. No module dependency: an OS notification API needs FSEvents (cgo) on macOS or one kqueue descriptor per file, and inotify on Linux would mean two implementations; a second's latency is enough for a file explorer. The walk stops at 20 000 entries (`watched`, `truncated` and the hint "watch a subdirectory"). `excluded` lists what is skipped: directories named `.git`, `.gradle`, `.idea`, `.kotlin`, `.cxx`, and a `build` directory whose parent holds `build.gradle` or `build.gradle.kts` (a module's outputs; a source package named `build` is kept), plus D6's temporary files. Interval and caps are constants until the configuration file has keys for them (as 1i D14).
- D8. **The topic `file.changes`.** Type `changes`, payload `{path, changes [{path, kind: created | modified | deleted, type}], truncated}`, at most 1000 changes per event (`truncated` then: re-list); type `stopped`, payload `{path, reason: workspaceClosed}`. The event's `workspace` is the id and its `operation` the `file.watch` call's operation id, and the bus delivers it only to the subscription that call created: `Bus.subscribe` gains an optional match on the event (internal; `events.subscribe` unchanged). It is **not** added to `events.subscribe`'s topic enum: a subscription there would need a watcher nobody started, and would receive every workspace's changes. `file.watch` takes no `since`: a watcher that was not running produced nothing to replay, so after a reconnect the UI watches again and re-lists. The event payload is project content, not marked (R3).
- D9. **A watch's lifetime.** The poller ends when its subscription ends (`events.unsubscribe` of its id, which a `file.watch` id is, or the session's end) or when its workspace starts closing, which publishes `stopped` first (`workspace-state.md` §Cleanup: "release watchers"). Nothing is persisted (`workspace-state.md` §Durable vs ephemeral). A count of live pollers is exposed to tests so "no poller survives" is checkable.
- D10. **Descriptions** say paths are relative to the project root, that `file.read` pages like `artifact.read`, that `file.write` replaces the whole file atomically and creates parent directories, and (`file.watch`) that it is WebSocket-only and polls every second. The MCP server instructions are unchanged.
- D11. **Documents at the close** (step 4): a short `docs/subsystems/files.md` (D2–D9: the path rule, the codes, the write recipe, the watch and its topic; no other document holds them) and its map row; `capability-api.md` (classification row `file.watch` W/C, the topics table's `file.changes` row); `mcp-tool-surface.md` (the tool count); `docs/README.md` (rows Code, Next, Then); `docs/plans/README.md`.
