## Delegated decisions

Taken under the owner's standing instruction; each can be reverted.

- D1. **`file.*` only; `policy.*` and `shell.exec` in 1k.** They need the configuration specification (policy keys, device rules, `shell.exec` global and per workspace, how `droidyard trust` meets `policy.update`), which is design: an ADR, or an amendment to ADR-0031, must exist before the 1k plan, or that plan is `Blocked`. It can be written beside 1j's implementation, which needs none of it. Together they would pass ten steps and mix an authorization change with an unrelated domain.
- D2. **Paths.** `path` is relative to the workspace root, slash-separated; `""` and `"."` are the root. An absolute path is first stripped lexically of the canonical root (at a component boundary); only when that fails is its directory canonicalised with `platform.Env.Canonical` (as `workspace.open` canonicalises roots, so `/var/…` and `/private/var/…` agree) and its final component appended unresolved, then stripped again; otherwise `FILE_OUTSIDE_ROOT`. The final component therefore always reaches `os.Root` as written, so an absolute path to a link obeys the same link rules as a relative one (`Canonical` resolves every link, and would otherwise hand `os.Root` the link's target). A relative path that `filepath.IsLocal` rejects after cleaning is `FILE_OUTSIDE_ROOT`; a NUL byte, or `""` where a file is required, is `REQUEST_INVALID_PARAMS`. **Containment is `os.Root`'s**, opened on the canonical root for each call: every open, stat, mkdir and rename goes through it, so no check-then-open race exists. An `os.Root` refusal is classified by the error itself: a `*PathError` or `*LinkError` whose error is the standard library's escape (`"path escapes from parent"`; unexported, so its text is pinned by a test and a Go upgrade that changes it fails loudly) is `FILE_OUTSIDE_ROOT`. A symlink with an absolute target is therefore `FILE_OUTSIDE_ROOT` whatever it points to; relative symlinks inside the root are followed for reads.
- D3. **Codes.** `FILE_NOT_FOUND` (nextStep: `file.list` the parent); `FILE_OUTSIDE_ROOT` (`details {path, root}`; nextStep "pass a path inside the project root; files outside it are not reachable through droidyard"); `FILE_WRONG_TYPE` (a directory where a file is needed or the reverse, a FIFO, socket or device, a write to a symlink; `details {path, type}`); `FILE_IO_FAILED` (permissions, a read-only file, no space, anything else; `cause` the OS error). Not split further (ADR-0026's reasoning: `cause` says which). Each descriptor lists only the codes its handler returns; `WORKSPACE_NOT_OPEN` and `SESSION_REQUIRED` come from `Start` and are not listed.
- D4. **`file.list {path?, limit?}`** → `{path, entries [{name, type: file | dir | symlink | other, size?, modTime}], truncated, hint?}`: one level, never recursive; symlinks reported, not followed; `limit` 1–2000, default 500; names read in chunks up to 20 000 (cap while capturing), sorted bytewise, the first `limit` returned; `truncated` with the hint "list a subdirectory" when more exist (above 20 000 names the result is a sorted subset, not the first names). `Slim` drops `entries` after first delivery.
- D5. **`file.read {path, offset?, limit?}`** → `{path, size, modTime, offset, nextOffset, text?, truncated, binary}`, ADR-0012 §Reading artifacts' paging exactly. `artifact`'s paging is refactored to read from an open `io.ReaderAt` plus a size, so `file.read` pages the descriptor `os.Root` opened; `artifact.read` is unchanged (its tests untouched). Regular files only: opened `O_RDONLY|O_NONBLOCK` and `fstat`ed, so a FIFO is `FILE_WRONG_TYPE` at once. `binary: true` when the window holds a NUL or invalid UTF-8 (a rune cut by the window's end excepted): `text` omitted, `size` kept. `Slim` drops `text` after first delivery, as `artifact.read` does.
- D6. **`file.write {path, content}`** → `{path, size, created}`. `content` is UTF-8 of at most 512 KiB (else `REQUEST_INVALID_PARAMS`), so a request stays under the 1 MiB HTTP and WebSocket bound for ordinary text. Missing parents are created (`Root.MkdirAll`, 0755 before umask). Atomic, by ADR-0021 §Format's recipe applied to a project file: a temporary `.<name>.droidyard-<8 hex>.tmp` opened `O_CREATE|O_EXCL` in the target's directory (mode 0644, so the umask applies to a new file), written, `fsync`ed, given an existing target's exact mode through its own descriptor (`(*os.File).Chmod`, never the racy `Root.Chmod`), renamed over the target, the directory `fsync`ed; every failure path removes the temporary file. **The target keeps its on-disk name**: the rename's destination is the caller's final name when the directory lists it exactly; otherwise, among the entries equal to it under case folding and Unicode normalisation, the one `os.SameFile` matches with the target's `Lstat` (never any other name sharing the inode, so a hard-linked sibling is not chosen). So on a case- or normalisation-insensitive volume `src/a.kt` replaces `src/A.kt` without renaming it, and the result's `path` carries that final name (parent components as the caller wrote them). Refused: a directory, a FIFO or other special file, or a symlink as target (`FILE_WRONG_TYPE`: a rename replaces the link, not its target); a parent that is a file (`FILE_WRONG_TYPE`); an existing file without its owner-write bit (`FILE_IO_FAILED`, cause "read-only file": a rename would defeat the mark). Any `ENOENT` during a write (a dangling in-root parent link, a temporary file removed before the rename) is `FILE_IO_FAILED`, since the write's list has no `FILE_NOT_FOUND`. A hard link to the old file keeps the old content (said in the description). Writes under `.git/` are allowed: the agent's own tools can do the same behind its host's approval, and `file_write` is annotated destructive, so hosts prompt. **A daemon killed between the temporary file and the rename leaves it in the project**: a transient file, not state (ADR-0021 §Location), named so a human recognises it, ignored by `file.watch`. Works on an untrusted root (ADR-0015 §5).
- D7. **`file.watch {path?}`** → `{subscriptionId, watched, truncated, excluded []}`. A **command**, as `events.subscribe` (it creates a subscription; `mcp-tool-surface.md` §Annotations), settling `capability-api.md`'s "Q (to revisit)"; `Streaming`, so WebSocket-only (ADR-0010). **It polls**: the handler walks the directory through `os.Root`'s `FS()` (symlinks not followed) and records type, size and modification time per entry, then a goroutine walks again every second and publishes the differences. No module: an OS API needs FSEvents (cgo) on macOS or one kqueue descriptor per file, plus inotify on Linux; a second's latency suits a file explorer. Each walk stops at 20 000 entries (`watched`, `truncated`, hint "watch a subdirectory"); a tick that reaches the cap reports nothing deleted past it and marks its event `truncated`, so an entry pushed past the cap is never reported deleted; an entry past the cap that later falls under it is reported `created` (the hint says so: re-list). `excluded`: directories `.git`, `.gradle`, `.idea`, `.kotlin`, `.cxx`, a `build` directory whose parent holds `build.gradle` or `build.gradle.kts` (a source package named `build` is kept), and D6's temporary files. Interval and caps are constants until the configuration file has keys for them (as 1i D14).
- D8. **The topic `file.changes`.** Type `changes`, payload `{path, changes [{path, kind: created | modified | deleted, type}], truncated}`, at most 1000 changes per event; type `stopped`, payload `{path, reason: workspaceClosed}`. The event carries the workspace id and, as `operation`, the `file.watch` call's id. **It takes a seq but never enters the replay ring** and is offered only to its watch's subscription, through a bus method beside `Publish` (the ring's 4096 events and 4 MiB, sized in 1d for `workspace.lifecycle` and `operation.progress`, would otherwise be flushed by a busy watch, costing other subscribers' `since` a gap). It is not in `events.subscribe`'s enum. No `since`: a watcher that was not running produced nothing to replay, so after a reconnect the UI watches again and re-lists (`http-websocket.md` §`GET /v1/ws`'s resume sentence is amended at the close). Not marked (R3).
- D9. **A watch's lifetime.** The poller ends when its subscription ends (`events.unsubscribe` of its id, or the session's end) or when its workspace closes (the close hook, which runs after the drain, `workspace.go` `Close`); in that case the poller publishes `stopped` as its own last act, after its loop has ended, so nothing follows it. The subscription stays open until the session or the client ends it, so `stopped` is delivered (`Subscription.Close` discards its queue). The handler closes its subscription and poller on every path that does not return an id (an error, a cancel during the walk), re-checks `ctx.Err()` as its last act and cleans up on a cancel, and the poller set refuses a workspace that is not open. A narrow window remains, stated as a limit: a close's forced cancel landing after that last check ends the operation `cancelled` with the subscription created, which then holds `stopped` until the session ends. The close hook signals the poller and never waits for it while holding `bus.mu` (both `Subscription.Close` and publishing take it). Nothing is persisted. A live-poller count is exposed to tests.
- D10. **Descriptions** say paths are relative to the project root (an absolute path inside it is accepted), that `file.read` pages like `artifact.read`, that `file.write` replaces the whole file atomically, keeps its name and mode and creates parents, and that `file.watch` is WebSocket-only and polls every second. Server instructions unchanged.
- D11. **Documents at the close** (step 4): a short `docs/subsystems/files.md` (D2–D9, which no document holds) and its map row; `capability-api.md` (`file.watch` W/C, the topics table's `file.changes` row, §Subscriptions' resume bullet: `file.changes` is not in the ring); `core-runtime.md` §Events (the same); `http-websocket.md` §`GET /v1/ws` (a watch does not resume with `since`); `workspace-state.md` §State model (watchers belong to a session's subscription); `mcp-tool-surface.md` (the tool count); `docs/README.md` (rows Code, Next, Then); `docs/plans/README.md`.

## Changes

Changes after approval: date, what changed, why, and the ADR if the change touches the design.

- 2026-10-07, step 1 (verifier B1): `file.read`'s binary check ran on the raw window at the unadjusted offset, not on the page ADR-0012's paging returns, so a negative offset inside a multibyte rune gave `binary: true` and a NUL past that window reached `text`. The check now runs on the returned page; a binary result keeps that page's `offset` and `nextOffset`, so paging continues past it (the binary verdict is per window, not per file).
- 2026-10-07, step 1 (verifier, non-blocking, fixed): `file.list` on a file says "not a directory" with `type: regular file`; a slimmed `file.list` result carries the hint "entries dropped after delivery; call file.list again", so `entries: []` is not mistaken for an empty directory; the path note states D2's rule that every absolute-target symlink is refused.
- 2026-10-07, step 1 (verifier, recorded, not changed): an absolute path whose *directory* is spelled through an alias (`/var/…`) is canonicalised with `Env.Canonical`, which resolves every intermediate link, so `/var/…/root/hop/A.kt` (`hop` leaving and re-entering the root) reads the in-root file that `hop/A.kt` refuses. Containment holds (only in-root bytes, opened through `os.Root`); the spellings disagree. A2's "intermediate symlinks" holds for root-relative and canonical-absolute spellings. Also: `artifact.ReadText` now opens a durable entry's file before the past-the-end early return, so a file deleted between lookup and read errors instead of returning an empty page.
