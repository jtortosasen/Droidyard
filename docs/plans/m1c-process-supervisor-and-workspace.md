## Acceptance

- [ ] A1. State files follow ADR-0021 §Format: every file carries `schemaVersion`; writes are atomic (`*.tmp`, `fsync`, `rename`, `fsync` of the directory); a file that fails to parse is renamed `*.corrupt-<timestamp>`, treated as absent and reported in `system.health`, and the daemon keeps running; a file of a newer version is never overwritten. Source: ADR-0021 §Format; Phase 0 deliverable "persistence". Proven by: step 1, step 4
- [ ] A2. On start, after taking the lock and before binding the socket, the daemon reconciles `processes.json`: a live process whose kernel start time matches its record has its process group terminated (graceful signal, then force); any other record is dropped; a process that is not ours is never signalled. Source: ADR-0021 §Pid records; `process-lifecycle.md` §Crash recovery. Proven by: step 2, step 7
- [ ] A3. The supervisor starts a described process only on first use and returns it once its readiness probe passes; writes its pid record at spawn and removes it at reap; never stops a process that has use in flight; stops it after its idle timeout once unused and starts it again on the next use; stops a process group with the graceful signal, its timeout, then `SIGKILL`; launches every child in its own process group. Source: Phase 0 deliverable "process supervisor"; `process-lifecycle.md` §Model, §Lifecycle states, §Startup, §Idle shutdown, §Shutdown, cancellation and no-orphans. Proven by: step 6
- [ ] A4. A supervised dummy sidecar starts lazily, idles out, and leaves no orphans after `workspace.close`, checked when `close` returns (ADR-0027 §Consequences); nor after `droidyard stop`; nor, once the next daemon has started, after the daemon is killed with `SIGKILL`. Source: Phase 0 acceptance; `mvp.md` §Definition of done ("`workspace.close` leaves no orphan processes"); ADR-0027 §Decision. Proven by: step 7
- [ ] A5. `workspace.open`, `workspace.describe` and `workspace.close` are published with the annotations of `mcp-tool-surface.md` §The MVP tool surface; a root and its id `<basename>-<12 hex of sha256(canonical root)>` name one workspace; `open` runs no project code, is a no-op on an open workspace, persists `ws/<wsid>/workspace.json` and `workspaces.json`; `describe` reports `trusted: false`; an open of a target that is not a readable directory or a known id ends `failed` with `WORKSPACE_ROOT_INVALID`, and a `workspace.json` of a newer `schemaVersion` opens the workspace `degraded` with `WORKSPACE_STATE_NEWER` in `degradedBy` and the file untouched; `close` cancels the workspace's operations for every session and completes when the workspace is `closed`, draining them for at most 10 s; from `closing`, other workspace-scoped calls get `WORKSPACE_NOT_OPEN`, and an `open` waits for `closed`, then opens; after a daemon restart every workspace is closed until reopened, and its durable configuration is restored. Source: ADR-0020 §Core primitives, §Scope and workspace addressing; ADR-0027 §Decision; `core-runtime.md` §Invocation. Proven by: step 3

## Steps

### 1. Durable JSON state: atomic writes, versions, corrupt files

- Builds: `internal/store`: `Write(path, v)` (adds `schemaVersion`; writes `<path>.tmp` `0600`, `fsync`, `rename`, `fsync` of the directory; creates directories `0700`) and `Read(path, current, &v)` with four outcomes: absent; read; corrupt (the file renamed to `<path>.corrupt-<UTC timestamp>` with its bytes intact, treated as absent, and recorded); newer (`schemaVersion` above `current`: the file untouched, recorded, `ErrNewer` returned, and any later `Write` to that path refused with `ErrNewer`). A store-wide list of problems `{file, problem, movedTo?}` for step 4. No migrations: every file starts at version 1, so only the version check exists.
- Implements: ADR-0021 §Format (all four rules), §Location ("never inside the project tree": the store writes only under the state root it is given).
- Check: tests on a real temporary directory on APFS: a write leaves no `*.tmp` and the file parses with `schemaVersion` 1; the directory `fsync` returns no error; a `rename` that fails (the target is a non-empty directory) leaves the previous content intact; garbage reads as absent, is moved to `*.corrupt-*` byte for byte and listed as a problem; `schemaVersion` 2 reads as newer, its bytes unchanged, and a `Write` to it fails with `ErrNewer` and changes nothing; a stale `*.tmp` from an interrupted write is ignored by `Read` and replaced by the next `Write`. Seen failing with each decision reversed (no rename of a corrupt file; a newer file overwritten; no directory `fsync`, caught by a fake that records the call order).
- Schema: no change.
- Needs: nothing earlier.
- Not here: reporting problems in `system.health` (step 4); the files themselves (steps 2, 3); `daemon.log` rotation (Not in this milestone).
- Rests on: `File.Sync` on a directory descriptor succeeds on APFS (Go uses `F_FULLFSYNC` on darwin) and `rename` within one directory is atomic. Level 4 (real filesystem, in process). Durability across power loss cannot be provoked: Unverified.
- [ ] Done. Evidence:

### 2. Pid records, kernel start times, and reaping on start

- Builds: `internal/platform`: `StartTime(pid)`, darwin through `unix.SysctlKinfoProc("kern.proc.pid", pid)` (`Proc.P_starttime`), linux from `/proc/<pid>/stat` field 22 (parsed after the last `)`), with a distinct "no such process" result. `internal/process`: the record `{id, kind, workspace?, pid, pgid, startTime, command}` and `processes.json` (`{schemaVersion, processes: [...]}`, Readings R8) through `internal/store`; `Reconcile`: for each record whose pid is alive with the recorded start time, `SIGTERM` to `-pgid`, a 5 s wait (R11), `SIGKILL` to `-pgid`; every other record dropped; the emptied file written; each action logged. A newer `processes.json` is left untouched and recorded (R10). `internal/daemon`: `Reconcile` runs after `Acquire` and before the socket is bound: "on start, before spawning anything", by the single writer.
- Implements: ADR-0021 §Pid records, §Format (single writer); ADR-0019 `Amended: 2026-09-30` (`SysctlKinfoProc`); `process-lifecycle.md` §Crash recovery; `workspace-state.md` §Cleanup and crash recovery.
- Check: real processes on macOS. `StartTime` of a live child is stable across reads, two children started apart differ, and a reaped child reports no such process. Reaping: the test starts helper A (the test binary re-executed, `Setpgid`), which forks a grandchild into its group, and records A with its true start time; starts helper B in its own group and records it with its start time plus one second (standing in for pid reuse); records a pid that has been reaped. Then a re-executed `droidyard serve` on that state: when its socket first answers, A and its grandchild are gone (`kill -0` fails), B is alive and its `SIGTERM` handler fired nothing, `processes.json` lists no process, and `serve`'s log names A's record as reaped. Seen failing with each decision reversed: matching on pid alone (B is killed), killing the pid instead of the group (the grandchild survives), reconciling after the socket is bound (the socket answers while A lives).
- Schema: no change.
- Needs: step 1; `golang.org/x/sys/unix`, already required.
- Not here: writing records at spawn (step 6); a Linux run; a record whose leader died while other members of its group live: ADR-0021 drops it, so those members survive (Unverified).
- Rests on: a kernel start time tells our orphan from a process that reused its pid (`p_starttime`, microseconds, on macOS). Level 5 for the kill and no-kill decisions on real processes; real pid reuse cannot be provoked, so the offset start time stands for it.
- [ ] Done. Evidence:

### 3. The workspace model in process: identity, open, describe, close, `WORKSPACE_NOT_OPEN`

- Builds: `internal/platform`: canonicalisation exported (the rule the socket path already uses) and `WorkspaceID(root)`. `internal/workspace`: the in-memory registry of workspaces and their states (`opening`, `ready`, `degraded`, `closing`, `closed`); `ws/<wsid>/workspace.json` `{schemaVersion, root, name, createdAt}` and `workspaces.json` `{schemaVersion, workspaces: {<wsid>: {root, name, lastOpenedAt}}}` (R8); target resolution (R5). `open`: canonicalise, derive the id, validate a readable directory, load or create `workspace.json`, update the index, `trusted` false (R1); a target that is not an existing readable directory, or an id no index holds, ends the operation `failed` with `WORKSPACE_ROOT_INVALID`, `details {target}`, nextStep "call `workspace.open` with the absolute path of a readable project directory"; a `workspace.json` whose `schemaVersion` is above 1 is left untouched and the workspace opens `degraded` with `WORKSPACE_STATE_NEWER` in `degradedBy`, nextStep "upgrade droidyard, or delete `<state>/ws/<wsid>/` to reset this workspace" (ADR-0026 §Decision). `describe`. `close` (ADR-0027 §Decision): enter `closing`; cancel the workspace's operations and wait for them up to a drain bound, 10 s by default and injectable for tests; log any still running and leave it to end `cancelled`; a hook that step 7 fills with stopping the workspace's sidecars; then `closed`, and the call completes. The close handler ignores its own cancellation. `open` and `close` of one workspace are serialised by a per-workspace mutex held across the whole transition: an `open` during `closing` waits for `closed`, then opens; a second `close` waits and completes as a no-op. The three capabilities (R6, R7). `internal/capability`: `Start` resolves the target through an interface it is given (`capability` imports no `workspace`), sets `Call.Workspace` to the canonical id, and rejects with `WORKSPACE_NOT_OPEN` (nextStep `workspace.open`) unless the workspace is `ready` or `degraded`, or the capability is `workspace.open` or `workspace.close` (an unpublished descriptor flag), which receive the target unresolved so that their handlers judge it (ADR-0026: validation is the handler's, and ADR-0020's `Start` rejection list is unchanged). The open-state check and the recording of the operation in its workspace happen under one lock that `close` takes to enter `closing`. Both registries that must agree (`cmd/droidyard/main.go`, `internal/schema/schema_test.go`) register the three. `system.Version` becomes `0.2.0` (R2).
- Implements: ADR-0020 §Core primitives, §Scope and workspace addressing; ADR-0026 §Decision; ADR-0027 §Decision; ADR-0021 §Format (a newer file never overwritten), §Layout (the id rule, `ws/<wsid>/workspace.json`, `workspaces.json`); ADR-0015 §5 (open runs no project code; `describe` reports `trusted`); `workspace-state.md` §Lifecycle, §Identity and reuse, §Durable vs ephemeral state; `core-runtime.md` §Invocation, §Package layout (`internal/workspace`).
- Check: in-process tests with `-race`, one decision each. Identity and open: `/tmp/x`, `/private/tmp/x` and a case variant yield one id; `open` of a temporary directory answers `ready`, `trusted: false`, and writes both files with `schemaVersion` 1; a second `open` returns the same state and keeps `createdAt`; `open` by the id of an indexed workspace opens it; `open` of a root holding an executable `gradlew` that would write a marker leaves no marker. ADR-0026: `open` of a missing absolute path, of a regular file, of a directory without read permission, and of an id no index holds each creates an operation that ends `failed` with `WORKSPACE_ROOT_INVALID`, `details.target` the target as given, and the nextStep above; a `workspace.json` with `schemaVersion` 2 opens the workspace `degraded`, its bytes and mtime unchanged after `open` and `describe`, and both answers carry `degradedBy.code` `WORKSPACE_STATE_NEWER` with the nextStep above. `Start`: a workspace-scoped fixture call on a target not open gets `WORKSPACE_NOT_OPEN` with nextStep naming `workspace.open`, no operation, handler not run. ADR-0027, with the drain bound injected as 200 ms: `close` while a fixture that honours its context runs in that workspace returns only after the fixture has ended `cancelled` with `OPERATION_CANCELLED`, while a fixture in another workspace runs on; `close` while a fixture that ignores its context runs returns between 200 ms and 1 s, the workspace `closed`, a log line naming the operation, and the operation, still `running`, ends `cancelled` once released; while that close drains, a workspace-scoped fixture call gets `WORKSPACE_NOT_OPEN` at `Start`, an `open` returns only after the close has, and answers `ready`, and a second `close` returns after the first and completes; `operation.cancel` on the close operation while it drains leaves it to end `completed` with the workspace `closed`; `describe` after `close` gets `WORKSPACE_NOT_OPEN`; `close` of a target not open completes as a no-op; the drain bound wired in production is 10 s. Seen failing with each decision reversed (close returning at `closing`; no drain bound; an open during `closing` rejected; the open check and the operation's recording under separate locks, caught by a `-race -count=50` loop of `Start` against `close`). Then `go test ./internal/schema` fails with exactly the diff below, and `-update` is run only if it is that.
- Schema: `version` `0.1.0` → `0.2.0` (R2). Three entries, `since` `0.2.0`, scope `workspace`, statefulness stateless, input `{}`. `workspace.open`: kind command, idempotent; annotations `readOnlyHint` false, `destructiveHint` false (override, reason "registers a root and runs no project code", `mcp-tool-surface.md` §The MVP tool surface, its overrides list), `idempotentHint` true, `openWorldHint` false; output the workspace object; errors `WORKSPACE_ROOT_INVALID`, `WORKSPACE_STATE_NEWER` (ADR-0026). `workspace.describe`: kind query; read-only, idempotent, not open-world; output the workspace object; errors `WORKSPACE_STATE_NEWER` (ADR-0026; R7). `workspace.close`: kind command, idempotent; `destructiveHint` true (the default, kept per the overrides list), `openWorldHint` false; output `{}`; errors none. The workspace object: `{id, name, root, state, trusted, createdAt, degradedBy?}`, `state` one of `ready`, `degraded`, `degradedBy` the error shape `{code, message, cause?, nextStep?, details?}` (ADR-0026 §Consequences). The four existing entries are unchanged, `since` `0.1.0` included.
- Needs: step 1.
- Not here: stopping the workspace's sidecars on `close` (step 7 fills the hook); the CLI and MCP filling `workspace` (steps 4, 5); `workspace.lifecycle` events (1d); `sdkRoot` and project facts (Phase 1, additive: R6); trust from configuration and `WORKSPACE_UNTRUSTED` (Phase 1, R1); the drain bound in the configuration file (Phase 1, ADR-0027 §Consequences).
- Rests on: an operation that passes `Start`'s open check is always among those `close` cancels, because both happen under one lock; and `Start` and the id derivation canonicalise with one function, so a root and its id name one workspace whatever the spelling. Level 4 (in process, `-race`).
- [ ] Done. Evidence:

### 4. The CLI end to end: `--workspace`, the cwd's root, restart, and state problems in `system.health`

- Builds: a root resolver shared by both shims (`--root` if given, else the nearest ancestor of the cwd containing `settings.gradle` or `settings.gradle.kts`, else the cwd). `adapters/cli`: `--workspace <id|root>`, sent verbatim in the envelope. `cmd/droidyard call`: the hello's `root` is the resolved root of the cwd. `internal/daemon` `Native`: a request for a workspace-scoped capability that names no workspace gets the session's hello `root` (R3). `system.health` gains `stateProblems` from the store (R9).
- Implements: ADR-0020 §Scope and workspace addressing ("the CLI from `--workspace`, else the cwd's root"); ADR-0026 §Decision; ADR-0019 §Processes 7 (hello `root`), §Sessions (the root rule); ADR-0021 §Format ("reported in `system.health`. Corrupt state never stops the daemon"); `workspace-state.md` §Cleanup and crash recovery ("treats every workspace as closed until reopened").
- Check: re-executed `serve` and CLI, a temporary project with `settings.gradle.kts` and a subdirectory. From the subdirectory: `call workspace.open`, then `call workspace.describe`: `root` is the project directory, `id` and `name` follow the rule. From `/`: `call --workspace <id> workspace.describe` answers the same; `call --workspace <root> system.health` gets `REQUEST_UNEXPECTED_WORKSPACE`. `call workspace.close`, then `describe`: `WORKSPACE_NOT_OPEN`, exit non-zero. `stop`, `serve` again: `describe` gets `WORKSPACE_NOT_OPEN`; `open` gives the same id and `createdAt`, and a later `lastOpenedAt`. - Schema: `system.health`'s output gains the optional array `stateProblems` of `{file, problem, movedTo?}`, `problem` one of `corrupt`, `newerVersion`; nothing else.
- Needs: steps 1, 3.
- Not here: `droidyard trust` (Phase 1); relative paths for `--workspace` (the envelope takes an id or an absolute root; R5); MCP (step 5).
- Rests on: the shims send the root as resolved and only the daemon canonicalises it, so the CLI, MCP and the core derive one id. Level 5.

### 5. The MCP session binding, and opening the bound root at session start

### 6. The supervisor: descriptors, lazy start, readiness, idle shutdown, stop

- Builds: `internal/process`: a descriptor `{id, kind (shared-sidecar | workspace-sidecar), command, args, dir, env, scope (global | workspace:<id>), readiness (a probe on the process's output, never a sleep), idleTimeout, shutdown {signal, timeout}, logSink (a bounded buffer of output lines)}`. `Use(ctx, descriptor)` starts the process on first use (`Setpgid`; stdin a pipe the supervisor holds; stdout and stderr drained), writes its pid record as soon as the pid is known, waits for readiness, and returns a lease; leases are counted; at zero an idle timer runs, and on expiry the process stops if still unused; `Use` fails at once, spawning nothing, when its `ctx` is done, so an operation cancelled by a close and left running past the drain cannot start a sidecar again (ADR-0027); an unexpected exit marks it `failed` and removes its record, and the next `Use` starts it afresh. `Stop(scope)` and `Shutdown()` are explicit stops and ignore leases (idle shutdown alone respects them): the signal to the group, the descriptor's shutdown timeout, `SIGKILL` to the group, reap, record removed. States `starting`, `ready`, `busy`, `idle`, `stopping`, `stopped`, `failed`, readable in process. Every spawn happens on one goroutine locked to its OS thread for the supervisor's life; on Linux each child gets `Pdeathsig: SIGTERM`. With a newer `processes.json`, `Use` fails and spawns nothing (R10). The dummy, test-only: the test binary re-executed in a sidecar mode that prints a ready line, answers each stdin line, and exits on stdin EOF; options to ignore EOF and `SIGTERM`, to fork a helper into its group, and to write a lot of output.
- Implements: `process-lifecycle.md` §Model (without `health` and `restart`), §Lifecycle states, §Startup (lazy, readiness per process), §Idle shutdown ("never interrupt an in-flight operation"; "auto-restart on next use"), §Shutdown, cancellation and no-orphans (own process group; layer 1 stdin EOF; layer 2 `Pdeathsig` with the locked thread; layer 3 records), §Output handling (bounded buffers); ADR-0021 §Pid records (written at spawn, removed at reap).
- Check: real processes on macOS, `-race`: no process and no record before the first `Use`; the first `Use` returns after the ready line, with a record whose start time matches the live pid; with a lease held past `idleTimeout` the process stays; once released it stops within `idleTimeout` plus a margin, its record removed, state `stopped`; the next `Use` starts a new pid; `Stop` on a dummy that ignores `SIGTERM` and forked a helper leaves neither alive after the timeout, record removed; `Stop` with a lease held stops the process; `Use` with a cancelled `ctx` returns an error and spawns nothing; a dummy killed from outside becomes `failed`, its record removed, and the next `Use` starts it; `Shutdown` stops every process; a dummy writing megabytes is not blocked and the sink holds no more than its bound; with a newer `processes.json` `Use` fails and nothing is spawned. Seen failing with each decision reversed (idle stop with a lease held; the pid killed instead of the group; the record written after readiness; `Use` ignoring a done `ctx`).
- Schema: no change.
- Needs: steps 1, 2.
- Not here: restart policy and health probes, and the per-root `connection.close` of a shared sidecar (with the first shipped sidecar: Not in this milestone); per-operation children such as `logcat` streams (device slice); `process.lifecycle` and `process.output` events (1d); idle-timeout defaults (`process-lifecycle.md` §Open questions; set by the first real sidecar).
- Rests on: the final `SIGKILL` reaches the group while its leader is still unreaped, so its pgid cannot have been reused. Level 5 for the effect on macOS; the reuse window itself cannot be provoked (Unverified).
- [ ] Done. Evidence:

## Design questions

None open. The first draft (2026-10-02) was `Blocked` on two questions; the owner decided both on 2026-10-03, as new ADRs rather than the amendments to ADR-0020 the drafts proposed.

### Resolved on 2026-10-03

- **Q1, the error codes of `workspace.open`** (steps 3, 4, 5): [ADR-0026](../adr/0026-workspace-addressing-invalid-roots.md). `WORKSPACE_ROOT_INVALID` for a target that is not an existing, readable directory or an id no workspace index holds: the operation ends `failed`, `details {target}`, nextStep "call `workspace.open` with the absolute path of a readable project directory"; ADR-0020's `Start` rejection list is unchanged. `WORKSPACE_STATE_NEWER` for a `workspace.json` of an unread `schemaVersion`: the workspace opens `degraded`, the file is never overwritten, `workspace.open` and `workspace.describe` carry the error in `degradedBy`, nextStep "upgrade droidyard, or delete `<state>/ws/<wsid>/` to reset this workspace". The golden file lists them on `workspace.open` and `workspace.describe`. The decision matches the plan's draft; it was not an amendment to ADR-0020 but a new ADR that "relates to" it.
- **Q2, when `workspace.close` completes** (steps 3, 7): [ADR-0027](../adr/0027-workspace-close-and-reopen.md). `close` completes when the workspace is `closed`; entering `closing` rejects every other workspace-scoped call at `Start` with `WORKSPACE_NOT_OPEN`; operations are cancelled and waited on for up to 10 s (working default), one still running then is logged and left to end `cancelled`, then the workspace's sidecars stop (shutdown timeout, then `SIGKILL` of the group); a close is not cancellable once begun; `open` and `close` of one workspace are serialised. The decision matches the plan's draft. One addition: the 10 s bound is to move to the configuration file in Phase 1 (ADR-0027 §Consequences); step 3 keeps it a constant until then.

The decision section of ADR-0026 and the consequences of ADR-0027 both say that the `workspace-state.md` §Lifecycle section (and, for ADR-0026, the §Format section of ADR-0021) state the decided rules, and ADR-0027 that `workspace-state.md` drops its open question. As of `f1a46bd` none of those documents has been edited: see Readings R14.

## Readings the steps take

Not questions: each follows from a cited document and is cheap to change. The owner may promote any of them to a question.

- **R1. Trust.** ADR-0015 §5: a root is trusted only if it falls under a configured prefix or through an explicit human act, and "trust on first open" was rejected. 1c reads no configuration (no format exists) and has no human channel (`trust` and `policy.update` are Phase 1), so `trusted` is `false` for every root. No 1c capability runs project code, so `WORKSPACE_UNTRUSTED` has no caller yet.
- **R2. Version `0.2.0`.** 1b kept `0.1.0` because nothing had been released "to a consumer" and nothing was reachable by an agent; the second is no longer true (OpenCode, verified). `capability-api.md` §Error model puts new codes in a minor version, and ADR-0019 §7 detects a stale daemon only by a differing version: a 1b daemon auto-started for OpenCode would otherwise accept a 1c shim's hello and ignore its `root`. The three new capabilities carry `since` `0.2.0`; the protocol stays 1.
- **R3. The CLI's default workspace.** ADR-0020: "the CLI from `--workspace`, else the cwd's root". The shim does not know a capability's scope, and the envelope rejects a workspace on a global call, so the CLI shim sends its cwd's root in the hello (ADR-0019 §7's `root?`, not restricted to MCP), and the daemon's native handler fills `workspace` from it for a workspace-scoped capability whose request names none. "The cwd's root" uses the only root rule documented, ADR-0019 §Sessions.
- **R4. When the bound root opens.** ADR-0019 says "when the MCP session initializes"; `mcp-tool-surface.md` says "when the session starts". The adapter opens it after the hello and before it reads the first MCP message: no client can observe the difference, and the order does not depend on `mcp-go`'s hook timing (level 2 only).
- **R5. Targets.** An envelope `workspace` starting with `/` is a root, canonicalised to an id; anything else is an id. The CLI passes `--workspace` verbatim, since the envelope takes "a workspace id or an absolute project root".
- **R6. Result shapes.** `open` returns the workspace's state ("a no-op returning its state", `workspace-state.md`), the same object as `describe`; `close` returns `{}`, as `operation.cancel` does. The object carries the identity fields of `workspace-state.md` §State model that exist in 1c; `sdkRoot` is added with the SDK subsystem, an additive change.
- **R7. Error lists.** `WORKSPACE_NOT_OPEN` is a `Start` rejection, cross-cutting like `REQUEST_MISSING_WORKSPACE`, so no descriptor lists it. A descriptor lists the codes its handler returns (`capability-api.md` §Error model), plus, by ADR-0026, `WORKSPACE_STATE_NEWER` on `workspace.describe`, which carries it in a completed result's `degradedBy` rather than returning it. `workspace.describe` does not list `WORKSPACE_ROOT_INVALID`: a target that cannot be opened is never open, so `describe` on it is rejected at `Start`. That is this plan's reading of ADR-0026's "the golden file lists them on `workspace.open` and `workspace.describe`".
- **R8. File shapes.** `processes.json` `{schemaVersion, processes: [{id, kind, workspace?, pid, pgid, startTime, command}]}`, the fields of ADR-0021 §Pid records; `startTime` is the kernel's value as an opaque integer, compared for equality only. `workspaces.json` `{schemaVersion, workspaces: {<wsid>: {root, name, lastOpenedAt}}}`; `workspace.json` `{schemaVersion, root, name, createdAt}`, `name` the root's basename. The recipe's `snapshot` reads pids with `jq '.. | .pid?'`, which works on this shape.
- **R9. `stateProblems`.** ADR-0021 requires corrupt files to be "reported in `system.health`" and names no field: an optional array `{file, problem, movedTo?}`, `problem` `corrupt` or `newerVersion`, in lowerCamelCase per `capability-api.md` §Enum spelling.
- **R10. A newer `processes.json`.** ADR-0021: never overwritten. A spawn the daemon cannot record breaks the no-orphans guarantee, so the supervisor refuses to spawn and the problem shows in `system.health`. No shipped capability spawns in 1c.
- **R11. Reaping waits 5 s** between `SIGTERM` and `SIGKILL`. ADR-0021 says "wait, then `SIGKILL`" with no figure, and a record has no shutdown timeout. A constant.
- **R12. The dummy sidecar is test-only**, as 1b's fixtures are: ADR-0019 §3 fixes the complete subcommand set, and a debug capability would enter the published schema and the MCP tool list. The recipe's two rows that assume a shipped capability are replaced by step 7's tests, which `verify-daemon` §Keeping it true allows.
- **R13. A failed bound open.** ADR-0020: "A failure does not fail the session: workspace tools then return the error." ADR-0026: the binding "degrades to `WORKSPACE_NOT_OPEN` on every workspace tool until `workspace_open` shows the cause". The adapter keeps no error state (adapters translate only, `capability-api.md` §Mapping to adapters): workspace tools get the core's `WORKSPACE_NOT_OPEN`, and `workspace_open` returns `WORKSPACE_ROOT_INVALID`.
- **R14. Documents that do not yet restate ADR-0026 and ADR-0027.** `workspace-state.md` §Lifecycle names neither code nor the close rule, and §Open questions still lists the reopen-while-draining question that ADR-0027 closes; ADR-0021 §Format says a newer file opens the workspace "`degraded` with a clear error" and names no code; ADR-0020 §Scope and workspace addressing does not point to either ADR. The plan follows the ADRs, which win; those edits belong to the session that owns the documents, before or with step 3, so the checks and the documents agree when the step is verified.
- **R15. Close's operation.** `workspace.close` is an operation like any other, so `operation.cancel` on it is accepted; ADR-0027 makes the close itself not cancellable, so its handler ignores its context and the operation ends `completed` (an operation ends `cancelled` only when its handler returns an error, `internal/capability/operation.go` `run`).
