## Steps

### 1. Durable JSON state: atomic writes, versions, corrupt files

- Builds: `internal/store`: `Write(path, v)` (adds `schemaVersion`; writes `<path>.tmp` `0600`, `fsync`, `rename`, `fsync` of the directory; creates directories `0700`) and `Read(path, current, &v)` with four outcomes: absent; read; corrupt (the file renamed to `<path>.corrupt-<UTC timestamp>` with its bytes intact, treated as absent, and recorded); newer (`schemaVersion` above `current`: the file untouched, recorded, `ErrNewer` returned, and any later `Write` to that path refused with `ErrNewer`). A store-wide list of problems `{file, problem, movedTo?}` for step 4. No migrations: every file starts at version 1, so only the version check exists.
- Implements: ADR-0021 §Format (all four rules), §Location ("never inside the project tree": the store writes only under the state root it is given).
- Check: tests on a real temporary directory on APFS: a write leaves no `*.tmp` and the file parses with `schemaVersion` 1; the directory `fsync` returns no error; a `rename` that fails (the target is a non-empty directory) leaves the previous content intact; garbage reads as absent, is moved to `*.corrupt-*` byte for byte and listed as a problem; `schemaVersion` 2 reads as newer, its bytes unchanged, and a `Write` to it fails with `ErrNewer` and changes nothing; a stale `*.tmp` from an interrupted write is ignored by `Read` and replaced by the next `Write`. Seen failing with each decision reversed (no rename of a corrupt file; a newer file overwritten; no directory `fsync`, caught by a fake that records the call order).
- Schema: no change.
- Needs: nothing earlier.
- Not here: reporting problems in `system.health` (step 4); the files themselves (steps 2, 3); `daemon.log` rotation (Not in this milestone).
- Rests on: `File.Sync` on a directory descriptor succeeds on APFS (Go uses `F_FULLFSYNC` on darwin) and `rename` within one directory is atomic. Level 4 (real filesystem, in process). Durability across power loss cannot be provoked: Unverified.
- [ ] Done. Evidence:

### 2. Pid records, kernel start times, and reaping on start

- Builds: `internal/platform`: `StartTime(pid)`, darwin through `unix.SysctlKinfoProc("kern.proc.pid", pid)` (`Proc.P_starttime`), linux from `/proc/<pid>/stat` field 22 (parsed after the last `)`), with a distinct "no such process" result. `internal/process`: the record `{id, kind, workspace?, pid, pgid, startTime, command}` and `processes.json` (`{schemaVersion, processes: [...]}`, Readings R8) through `internal/store`; `Reconcile`: for each record whose pid is alive with the recorded start time, `SIGTERM` to `-pgid`, a 5 s wait (R11), `SIGKILL` to `-pgid`; every other record dropped; the emptied file written; each action logged. A newer `processes.json` is left untouched and recorded (R10). `internal/daemon`: `Reconcile` runs after `Acquire` and before the socket is bound: "on start, before spawning anything", by the single writer.
- Implements: ADR-0021 §Pid records, §Format (single writer); ADR-0019 `Amended: 2026-09-30` (`SysctlKinfoProc`); `process-lifecycle.md` §Crash recovery; `workspace-state.md` §Cleanup and crash recovery.
- Check: real processes on macOS. `StartTime` of a live child is stable across reads, two children started apart differ, and a reaped child reports no such process. Reaping: the test starts helper A (the test binary re-executed, `Setpgid`), which forks a grandchild into its group, and records A with its true start time; starts helper B in its own group and records it with its start time plus one second (standing in for pid reuse); records a pid that has been reaped. Then a re-executed `droidyard serve` on that state: when its socket first answers, A and its grandchild are gone (`kill -0` fails), B is alive and its `SIGTERM` handler fired nothing, `processes.json` lists no process, and `serve`'s log names A's record as reaped. Seen failing with each decision reversed: matching on pid alone (B is killed), killing the pid instead of the group (the grandchild survives), reconciling after the socket is bound (the socket answers while A lives).
- Schema: no change.
- Needs: step 1; `golang.org/x/sys/unix`, already required.
- Not here: writing records at spawn (step 6); a Linux run; a record whose leader died while other members of its group live: ADR-0021 drops it, so those members survive (Unverified).
- Rests on: a kernel start time tells our orphan from a process that reused its pid (`p_starttime`, microseconds, on macOS). Level 5 for the kill and no-kill decisions on real processes; real pid reuse cannot be provoked, so the offset start time stands for it.
- [ ] Done. Evidence:

### 3. The workspace model in process: identity, open, describe, close, `WORKSPACE_NOT_OPEN`

- Builds: `internal/platform`: canonicalisation exported (the rule the socket path already uses) and `WorkspaceID(root)`. `internal/workspace`: the in-memory registry of open workspaces and their states (`opening`, `ready`, `degraded`, `closing`, `closed`); `ws/<wsid>/workspace.json` `{schemaVersion, root, name, createdAt}` and `workspaces.json` `{schemaVersion, workspaces: {<wsid>: {root, name, lastOpenedAt}}}` (R8); target resolution (R5); `open`: canonicalise, derive the id, validate a readable directory, load or create `workspace.json`, update the index, `trusted` false (R1); `describe`; `close`: cancel the workspace's operations and reject new ones (Q2); the three capabilities (R6, R7). `internal/capability`: `Start` resolves the target through an interface it is given (`capability` imports no `workspace`), sets `Call.Workspace` to the canonical id, and rejects with `WORKSPACE_NOT_OPEN` (nextStep `workspace.open`) unless the workspace is open or the capability is `workspace.open` or `workspace.close` (an unpublished descriptor flag); the store records each operation's workspace so `close` can cancel them. Both registries that must agree (`cmd/droidyard/main.go`, `internal/schema/schema_test.go`) register the three. `system.Version` becomes `0.2.0` (R2).
- Implements: ADR-0020 §Core primitives, §Scope and workspace addressing; ADR-0021 §Format, §Layout (the id rule, `ws/<wsid>/workspace.json`, `workspaces.json`); ADR-0015 §5 (open runs no project code; `describe` reports `trusted`); `workspace-state.md` §Lifecycle, §Identity and reuse, §Durable vs ephemeral state; `core-runtime.md` §Invocation, §Package layout (`internal/workspace`).
- Check: in-process tests with `-race`, one decision each: `/tmp/x`, `/private/tmp/x` and a case variant yield one id; `open` of a temporary directory answers `ready`, `trusted: false`, and writes both files with `schemaVersion` 1; a second `open` returns the same state and keeps `createdAt`; `open` by the id of an indexed workspace opens it; a workspace-scoped fixture call on a target not open gets `WORKSPACE_NOT_OPEN` with nextStep naming `workspace.open`, no operation, handler not run; `open` of a root holding an executable `gradlew` that would write a marker leaves no marker; `close` while a fixture operation runs in that workspace ends it `cancelled` with `OPERATION_CANCELLED`, while a fixture operation in another workspace runs on; `describe` after `close` gets `WORKSPACE_NOT_OPEN`; `close` of a target not open completes as a no-op. *Pending Q1:* `open` of a missing path, of a file, and of an unknown id ends `failed` with `WORKSPACE_ROOT_INVALID`; a `workspace.json` of `schemaVersion` 2 opens `degraded`, the file unchanged, and `describe` carries `WORKSPACE_STATE_NEWER`. *Pending Q2:* `close` completes only after its operations have ended; an `open` issued during `closing` waits, then opens; a workspace-scoped call during `closing` gets `WORKSPACE_NOT_OPEN`. Then `go test ./internal/schema` fails with exactly the diff below, and `-update` is run only if it is that.
- Schema: `version` `0.1.0` → `0.2.0` (R2). Three entries, `since` `0.2.0`, scope `workspace`, statefulness stateless, input `{}`. `workspace.open`: kind command, idempotent; annotations `readOnlyHint` false, `destructiveHint` false (override, reason "registers a root and runs no project code", `mcp-tool-surface.md` §The MVP tool surface, its overrides list), `idempotentHint` true, `openWorldHint` false; output the workspace object; errors `WORKSPACE_ROOT_INVALID`, `WORKSPACE_STATE_NEWER` (pending Q1). `workspace.describe`: kind query; read-only, idempotent, not open-world; output the workspace object; errors `WORKSPACE_STATE_NEWER` (pending Q1). `workspace.close`: kind command, idempotent; `destructiveHint` true (the default, kept per §Overrides), `openWorldHint` false; output `{}`; errors none. The workspace object: `{id, name, root, state, trusted, createdAt, degradedBy?}`, `state` one of `ready`, `degraded`, `degradedBy` the error shape (pending Q1). The four existing entries are unchanged, `since` `0.1.0` included.

- Not here: stopping the workspace's sidecars on `close` (step 7); the CLI and MCP filling `workspace` (steps 4, 5); `workspace.lifecycle` events (1d); `sdkRoot` and project facts (Phase 1, additive: R6); trust from configuration and `WORKSPACE_UNTRUSTED` (Phase 1, R1).

### 6. The supervisor: descriptors, lazy start, readiness, idle shutdown, stop

- Builds: `internal/process`: a descriptor `{id, kind (shared-sidecar | workspace-sidecar), command, args, dir, env, scope (global | workspace:<id>), readiness (a probe on the process's output, never a sleep), idleTimeout, shutdown {signal, timeout}, logSink (a bounded buffer of output lines)}`. `Use(ctx, descriptor)` starts the process on first use (`Setpgid`; stdin a pipe the supervisor holds; stdout and stderr drained), writes its pid record as soon as the pid is known, waits for readiness, and returns a lease; leases are counted; at zero an idle timer runs, and on expiry the process stops if still unused; an unexpected exit marks it `failed` and removes its record, and the next `Use` starts it afresh. `Stop(scope)` and `Shutdown()`: the signal to the group, the timeout, `SIGKILL` to the group, reap, record removed. States `starting`, `ready`, `busy`, `idle`, `stopping`, `stopped`, `failed`, readable in process. Every spawn happens on one goroutine locked to its OS thread for the supervisor's life; on Linux each child gets `Pdeathsig: SIGTERM`. With a newer `processes.json`, `Use` fails and spawns nothing (R10). The dummy, test-only: the test binary re-executed in a sidecar mode that prints a ready line, answers each stdin line, and exits on stdin EOF; options to ignore EOF and `SIGTERM`, to fork a helper into its group, and to write a lot of output.
- Implements: `process-lifecycle.md` §Model (without `health` and `restart`), §Lifecycle states, §Startup (lazy, readiness per process), §Idle shutdown ("never interrupt an in-flight operation"; "auto-restart on next use"), §Shutdown, cancellation and no-orphans (own process group; layer 1 stdin EOF; layer 2 `Pdeathsig` with the locked thread; layer 3 records), §Output handling (bounded buffers); ADR-0021 §Pid records (written at spawn, removed at reap).
- Check: real processes on macOS, `-race`: no process and no record before the first `Use`; the first `Use` returns after the ready line, with a record whose start time matches the live pid; with a lease held past `idleTimeout` the process stays; once released it stops within `idleTimeout` plus a margin, its record removed, state `stopped`; the next `Use` starts a new pid; `Stop` on a dummy that ignores `SIGTERM` and forked a helper leaves neither alive after the timeout, record removed; a dummy killed from outside becomes `failed`, its record removed, and the next `Use` starts it; `Shutdown` stops every process; a dummy writing megabytes is not blocked and the sink holds no more than its bound; with a newer `processes.json` `Use` fails and nothing is spawned. Seen failing with each decision reversed (stop with a lease held; the pid killed instead of the group; the record written after readiness).
- Schema: no change.

## Design questions

The plan is `Blocked` until the owner decides both. The session that owns the workflow turns each into a `Proposed` ADR or amendment; nothing below binds until accepted.

### Q1. Which error codes does `workspace.open` return when its target cannot be opened, and when a workspace's state file is from a newer version?

- Blocks: steps 3, 4, 5 (the checks marked *Pending Q1*), and the `errors` lists and the `degradedBy` field in step 3's schema diff.
- The documents say: `workspace-state.md` §Lifecycle: `open` must "validate that it is a readable directory", with no outcome for a failure. ADR-0020 §Scope: the target is "a workspace id or an absolute project root", with no outcome for an id that names nothing. ADR-0021 §Format: a newer file means "the workspace opens `degraded` with a clear error", with no code. `capability-api.md` §Error model: every error has a code, codes are published in each descriptor, and "a code, once published, is never … given a new meaning"; `REQUEST_INVALID_PARAMS` means the params fail the input schema, and the target is not a param. The cross-cutting table has `WORKSPACE_NOT_OPEN` and `WORKSPACE_UNTRUSTED` only.
- Draft decision, as an amendment to ADR-0020 §Scope and workspace addressing:
  - **Context.** Phase 0 ships `workspace.open`, and an MCP binding to a mistyped `--root` reaches it at once. Without a code the handler has to borrow one, and every borrowed code here changes a published meaning.
  - **Decision.** Two codes in the `WORKSPACE` domain, listed by the descriptors that return them. `WORKSPACE_ROOT_INVALID`: the target of `workspace.open` is an absolute path that does not exist, is not a directory or cannot be read, or an id found in no workspace index. The operation ends `failed`, since validation is the handler's work in `workspace-state.md` §Lifecycle, so ADR-0020's list of `Start` rejections is unchanged; `details {target}`; nextStep "call `workspace.open` with the absolute path of a readable project directory". `WORKSPACE_STATE_NEWER`: `ws/<wsid>/workspace.json` has a `schemaVersion` this daemon does not read. The workspace opens `degraded`, the file is not overwritten, and `workspace.describe` and `workspace.open` carry the error in `degradedBy`; nextStep "upgrade droidyard, or delete `<state>/ws/<wsid>/` to reset this workspace" (ADR-0021 §Consequences).
  - **Consequences.** `workspace-state.md` §Lifecycle names the codes, and so does ADR-0021 §Format; the golden file lists them on `workspace.open` and `workspace.describe`. An MCP binding to a bad root degrades to `WORKSPACE_NOT_OPEN` on every tool until `workspace_open` shows the cause.
  - **Alternatives considered.** `REQUEST_INVALID_PARAMS`: gives a published code a second meaning. `WORKSPACE_NOT_OPEN` for a failed open: its nextStep is the call that just failed, so an agent loops. A rejection at `Start`: adds a filesystem check to every `Start` of `workspace.open` and amends ADR-0020's rejection list for no consumer-visible gain. Three codes (not found, not a directory, unreadable): every consumer reacts the same way, by fixing the path; `cause` says which. Treating a newer file as corrupt: renames a newer version's state away on a downgrade, which ADR-0021 forbids. Deferring the newer-version case until a binary writes version 2: possible, since no released binary writes one, but then 1c must still refuse to overwrite and has no way to say why; this alternative wins if the owner prefers fewer codes now.

### Q2. When does `workspace.close` complete, and what happens to an `open` of the same workspace while it is closing?

- Blocks: step 3 (the checks marked *Pending Q2*) and step 7 (close stopping sidecars).
- The documents say: `workspace-state.md` §Open questions: "Whether a workspace can be *reopened* while operations are still draining, or must fully close first", open. §Lifecycle: `closing` is "cancelling the workspace's operations, shutting down workspace-owned sidecars"; `closed` is "all resources released". §Concurrency model: "mutations are serialised by the owning domain service". ADR-0020 §Scope: close "cancels the workspace's operations (their waiters see `cancelled`)". `process-lifecycle.md` §Shutdown: operations are drained before sidecars are signalled. ADR-0020 §Adapter projections: a tool not flagged `LongRunning`, which `workspace_close` is not (`mcp-tool-surface.md`), must finish under 60 s. Phase 0 acceptance: no orphans "after `workspace.close`".
- Draft decision, as an amendment to ADR-0020 §Scope and workspace addressing, closing the open question in `workspace-state.md`:
  - **Context.** Two clients share one workspace, so a close and an open of it can overlap. If `close` returns before its sidecars are gone, "no orphans after `workspace.close`" cannot be checked when it returns; if it waits without a bound, a handler that ignores cancellation holds an MCP tool call past the client's timeout.
  - **Decision.** `workspace.close` completes when the workspace is `closed`. On entering `closing`, every workspace-scoped call on it except `open` and `close` is rejected at `Start` with `WORKSPACE_NOT_OPEN`; its operations are cancelled and waited for up to 10 s (working default); an operation still running then is logged and left to end `cancelled` when its handler returns; then its workspace sidecars stop (their shutdown timeout, then `SIGKILL` of the group). Once begun, a close is not cancellable: a half-closed workspace has no defined state. `open` and `close` of one workspace are serialised: an `open` that arrives during `closing` waits for `closed` and then opens; a second `close` waits and completes as a no-op.
  - **Consequences.** `workspace-state.md` §Lifecycle states the rule and drops the open question. Sidecar shutdown timeouts must leave `close` under 60 s: a constraint on the Gradle sidecar's descriptor later.
  - **Alternatives considered.** Close returns at `closing` and drains in the background: "no orphans after close" then holds only eventually, and an open during the drain either fails, which needs a code and an agent retry loop, or revives a half-closed workspace. Reject an open during `closing` with a new code: same retry loop, for a wait that is normally milliseconds. No bound on draining operations: one handler that ignores `ctx` keeps `workspace_close` past client timeouts, and the timeout's `notifications/cancelled` would cancel the close. Flag `workspace.close` `LongRunning`: changes a published tool to the operation view for a call that is normally instant.

## Readings the steps take

Not questions: each follows from a cited document and is cheap to change. The owner may promote any of them to a question.

- **R1. Trust.** ADR-0015 §5: a root is trusted only if it falls under a configured prefix or through an explicit human act, and "trust on first open" was rejected. 1c reads no configuration (no format exists) and has no human channel (`trust` and `policy.update` are Phase 1), so `trusted` is `false` for every root. No 1c capability runs project code, so `WORKSPACE_UNTRUSTED` has no caller yet.
- **R2. Version `0.2.0`.** 1b kept `0.1.0` because nothing had been released "to a consumer" and nothing was reachable by an agent; the second is no longer true (OpenCode, verified). `capability-api.md` §Error model puts new codes in a minor version, and ADR-0019 §7 detects a stale daemon only by a differing version: a 1b daemon auto-started for OpenCode would otherwise accept a 1c shim's hello and ignore its `root`. The three new capabilities carry `since` `0.2.0`; the protocol stays 1.
- **R3. The CLI's default workspace.** ADR-0020: "the CLI from `--workspace`, else the cwd's root". The shim does not know a capability's scope, and the envelope rejects a workspace on a global call, so the CLI shim sends its cwd's root in the hello (ADR-0019 §7's `root?`, not restricted to MCP), and the daemon's native handler fills `workspace` from it for a workspace-scoped capability whose request names none. "The cwd's root" uses the only root rule documented, ADR-0019 §Sessions.
- **R4. When the bound root opens.** ADR-0019 says "when the MCP session initializes"; `mcp-tool-surface.md` says "when the session starts". The adapter opens it after the hello and before it reads the first MCP message: no client can observe the difference, and the order does not depend on `mcp-go`'s hook timing (level 2 only).
- **R5. Targets.** An envelope `workspace` starting with `/` is a root, canonicalised to an id; anything else is an id. The CLI passes `--workspace` verbatim, since the envelope takes "a workspace id or an absolute project root".
- **R6. Result shapes.** `open` returns the workspace's state ("a no-op returning its state", `workspace-state.md`), the same object as `describe`; `close` returns `{}`, as `operation.cancel` does. The object carries the identity fields of `workspace-state.md` §State model that exist in 1c; `sdkRoot` is added with the SDK subsystem, an additive change.
- **R7. Error lists.** `WORKSPACE_NOT_OPEN` is a `Start` rejection, cross-cutting like `REQUEST_MISSING_WORKSPACE`, so no descriptor lists it; descriptors list only the codes their handlers return (`capability-api.md` §Error model).
- **R8. File shapes.** `processes.json` `{schemaVersion, processes: [{id, kind, workspace?, pid, pgid, startTime, command}]}`, the fields of ADR-0021 §Pid records; `startTime` is the kernel's value as an opaque integer, compared for equality only. `workspaces.json` `{schemaVersion, workspaces: {<wsid>: {root, name, lastOpenedAt}}}`; `workspace.json` `{schemaVersion, root, name, createdAt}`, `name` the root's basename. The recipe's `snapshot` reads pids with `jq '.. | .pid?'`, which works on this shape.
- **R9. `stateProblems`.** ADR-0021 requires corrupt files to be "reported in `system.health`" and names no field: an optional array `{file, problem, movedTo?}`, `problem` `corrupt` or `newerVersion`, in lowerCamelCase per `capability-api.md` §Enum spelling.
- **R10. A newer `processes.json`.** ADR-0021: never overwritten. A spawn the daemon cannot record breaks the no-orphans guarantee, so the supervisor refuses to spawn and the problem shows in `system.health`. No shipped capability spawns in 1c.
- **R11. Reaping waits 5 s** between `SIGTERM` and `SIGKILL`. ADR-0021 says "wait, then `SIGKILL`" with no figure, and a record has no shutdown timeout. A constant.
- **R12. The dummy sidecar is test-only**, as 1b's fixtures are: ADR-0019 §3 fixes the complete subcommand set, and a debug capability would enter the published schema and the MCP tool list. The recipe's two rows that assume a shipped capability are replaced by step 7's tests, which `verify-daemon` §Keeping it true allows.
- **R13. A failed bound open.** ADR-0020: "A failure does not fail the session: workspace tools then return the error." The adapter keeps no error state (adapters translate only, `capability-api.md` §Mapping to adapters): workspace tools get the core's `WORKSPACE_NOT_OPEN`, and `workspace_open` returns the cause.
