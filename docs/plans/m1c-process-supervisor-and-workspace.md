- [ ] A1. ## Steps

### 1. Durable JSON state: atomic writes, versions, corrupt files

- Builds: `internal/store`: `Write(path, v)` (adds `schemaVersion`; writes `<path>.tmp` `0600`, `fsync`, `rename`, `fsync` of the directory; creates directories `0700`) and `Read(path, current, &v)` with four outcomes: absent; read; corrupt (the file renamed to `<path>.corrupt-<UTC timestamp>` with its bytes intact, treated as absent, and recorded); newer (`schemaVersion` above `current`: the file untouched, recorded, `ErrNewer` returned, and any later `Write` to that path refused with `ErrNewer`). A store-wide list of problems `{file, problem, movedTo?}` for step 4. No migrations: every file starts at version 1, so only the version check exists.
- Implements: ADR-0021 §Format (all four rules), §Location ("never inside the project tree": the store writes only under the state root it is given).
- Check: tests on a real temporary directory on APFS: a write leaves no `*.tmp` and the file parses with `schemaVersion` 1; the directory `fsync` returns no error; a `rename` that fails (the target is a non-empty directory) leaves the previous content intact; garbage reads as absent, is moved to `*.corrupt-*` byte for byte and listed as a problem; `schemaVersion` 2 reads as newer, its bytes unchanged, and a `Write` to it fails with `ErrNewer` and changes nothing; a stale `*.tmp` from an interrupted write is ignored by `Read` and replaced by the next `Write`. Seen failing with each decision reversed (no rename of a corrupt file; a newer file overwritten; no directory `fsync`, caught by a fake that records the call order).
- Schema: no change.
- Needs: nothing earlier.
- Not here: reporting problems in `system.health` (step 4); the files themselves (steps 2, 3); `daemon.log` rotation (Not in this milestone).
- Rests on: `File.Sync` on a directory descriptor succeeds on APFS (Go uses `F_FULLFSYNC` on darwin) and `rename` within one directory is atomic. Level 4 (real filesystem, in process). Durability across power loss cannot be provoked: Unverified.

### 2. Pid records, kernel start times, and reaping on start

- Builds: `internal/platform`: `StartTime(pid)`, darwin through `unix.SysctlKinfoProc("kern.proc.pid", pid)` (`Proc.P_starttime`), linux from `/proc/<pid>/stat` field 22 (parsed after the last `)`), with a distinct "no such process" result. `internal/process`: the record `{id, kind, workspace?, pid, pgid, startTime, command}` and `processes.json` (`{schemaVersion, processes: [...]}`, Readings R8) through `internal/store`; `Reconcile`: every record whose pid is alive with the recorded start time gets `SIGTERM` to `-pgid`, all of them first; then one wait of at most 5 s for all of them together (R11), polling each group; `SIGKILL` to `-pgid` of every group still alive, then `kill(-pgid, 0)` polled for each until it fails with `ESRCH`, bounded at 1 s in total (a group still present then is logged by pgid); then every other record dropped, the emptied file written, each action logged. Signalling all first and waiting once bounds reconciliation at about 5 s whatever the number of records, inside the 10 s a shim retries after auto-starting a daemon (ADR-0019 §Processes 4); sequential waits would not be. A newer `processes.json` is left untouched and recorded (R10). `internal/daemon`: `Reconcile` runs after `Acquire` and before the socket is bound: "on start, before spawning anything", by the single writer. Test plumbing (R17): `internal/process/processtest`, an ordinary package that only tests import, holds the helper and dummy modes the re-executed test binary runs.
- Implements: ADR-0021 §Pid records, §Format (single writer); ADR-0019 `Amended: 2026-09-30` (`SysctlKinfoProc`); `process-lifecycle.md` §Crash recovery; `workspace-state.md` §Cleanup and crash recovery.
- Check: real processes on macOS. Start times: `StartTime` of a live child is stable across reads, two children started apart differ, and a reaped child reports no such process; a unit test parses recorded Linux `stat` lines, one whose command name contains `) (` and spaces, and reads field 22 counted after the last `)`; `GOOS=linux go vet ./...` prints nothing, so the `/proc` reader compiles. Reaping: every helper is the test binary re-executed in a helper mode (R17) in its own process group, and the test reaps each with `cmd.Wait` in a goroutine, so a dead helper is never a zombie whose `kill -0` succeeds and whose start time still reads. The helpers: A, which honours `SIGTERM` and has forked a grandchild into its group, recorded with its true start time; C1 and C2, which ignore `SIGTERM`, each recorded with its true start time; B, alive and recorded with its start time plus one second (standing in for pid reuse); and a record of a pid already reaped. Then a re-executed `droidyard serve` on that state, with the test dialling its socket every 50 ms from the moment it starts. Asserted: A and its grandchild are dead before the socket first answers; C1 and C2 are dead before the socket first answers, and not earlier than 5 s after `serve` started (the grace was honoured and the forced kill ran); the socket first answers less than 7 s after `serve` started (one wait for both, not two); B is alive and its `SIGTERM` handler recorded nothing; `processes.json` lists no process; `serve`'s log names A, C1 and C2 as reaped and C1 and C2 as killed. Seen failing with each decision reversed: matching on pid alone (B is killed); the pid killed instead of the group (A's grandchild survives); no `SIGKILL` after the wait (C1 survives); reconciling after the socket is bound (the socket answers while C1 lives); one wait per record (the socket first answers after 10 s).
- Schema: no change.
- Needs: step 1; `golang.org/x/sys/unix`, already required.
- Not here: writing records at spawn (step 6); a Linux run; a record whose leader died while other members of its group live: ADR-0021 drops it, so those members survive (Unverified).
- Rests on: a kernel start time tells our orphan from a process that reused its pid (`p_starttime`, microseconds, on macOS); and the daemon answers on its socket only after every orphan group is dead. Level 5 for the kill, no-kill and ordering decisions on real processes; real pid reuse cannot be provoked, so the offset start time stands for it.

### 3. The workspace model in process: identity, open, describe, close, `WORKSPACE_NOT_OPEN`

- Builds: `internal/platform`: canonicalisation exported (the rule the socket path already uses) and `WorkspaceID(root)`. `internal/workspace`: the in-memory registry of workspaces and their states (`opening`, `ready`, `degraded`, `closing`, `closed`); `ws/<wsid>/workspace.json` `{schemaVersion, root, name, createdAt}` and `workspaces.json` `{schemaVersion, workspaces: {<wsid>: {root, name, lastOpenedAt}}}` (R8); target resolution (R5). `open`: canonicalise, derive the id, validate a readable directory, load or create `workspace.json`, update the index, `trusted` false (R1); a target that is not an existing readable directory, or an id no index holds, ends the operation `failed` with `WORKSPACE_ROOT_INVALID`, `details {target}`, nextStep "call `workspace.open` with the absolute path of a readable project directory"; a `workspace.json` whose `schemaVersion` is above 1 is left untouched and the workspace opens `degraded` with `WORKSPACE_STATE_NEWER` in `degradedBy`, nextStep "upgrade droidyard, or delete `<state>/ws/<wsid>/` to reset this workspace" (ADR-0026 §Decision). `describe`. `workspaces.json` of a newer version is neither read nor written (R16). `close` (ADR-0027 §Decision): enter `closing`; cancel the workspace's operations and wait for them up to a drain bound, 10 s by default and injectable for tests; log any still running; a hook that step 7 fills with stopping the workspace's sidecars; then `closed`, and the call completes. An operation cancelled by a close ends `cancelled` with `OPERATION_CANCELLED` whatever its handler returns, when it returns ("left to end `cancelled`", ADR-0027): the store gains a forced cancel that close uses, while `operation.cancel` keeps 1b's rule (a handler that returns a result after a cancel ends `completed`, R15). `workspace.open` and `workspace.close` operations reach their handlers with the target unresolved and are not recorded as operations of the workspace, so a close never cancels or waits on itself, another close or an `open`. The close handler ignores its own cancellation. `open` and `close` of one workspace are serialised by a per-workspace mutex held across the whole transition: an `open` during `closing` waits for `closed`, then opens; a second `close` waits and completes as a no-op. The three capabilities (R6, R7). `internal/capability`: `Start` resolves the target through an interface it is given (`capability` imports no `workspace`), sets `Call.Workspace` to the canonical id, and rejects with `WORKSPACE_NOT_OPEN` (nextStep `workspace.open`) unless the workspace is `ready` or `degraded`, or the capability is `workspace.open` or `workspace.close` (an unpublished descriptor flag), which receive the target unresolved so that their handlers judge it (ADR-0026: validation is the handler's, and ADR-0020's `Start` rejection list is unchanged). The open-state check and the recording of the operation in its workspace happen under one lock that `close` takes to enter `closing`; a test-only hook inside `Start`, between the check and the recording, lets a test hold `Start` there. Both registries that must agree (`cmd/droidyard/main.go`, `internal/schema/schema_test.go`) register the three. `system.Version` becomes `0.2.0` (R2), and the two `system.*` descriptors, whose `Since` is `Version` today (`internal/domain/system/system.go`), get the literal `"0.1.0"`, the version that introduced them.

- Check: in-process tests with `-race`, one decision each. Identity and open: `/tmp/x`, `/private/tmp/x` and a case variant yield one id; `open` of a temporary directory answers `ready`, `trusted: false`, and writes both files with `schemaVersion` 1; a second `open` returns the same state and keeps `createdAt`; `open` by the id of an indexed workspace opens it; `open` of a root holding an executable `gradlew` that would write a marker leaves no marker. ADR-0026: `open` of a missing absolute path, of a regular file, of a directory without read permission, and of an id no index holds each creates an operation that ends `failed` with `WORKSPACE_ROOT_INVALID`, `details.target` the target as given, and the nextStep above; a `workspace.json` with `schemaVersion` 2 opens the workspace `degraded`, its bytes and mtime unchanged after `open` and `describe`, and both answers carry `degradedBy.code` `WORKSPACE_STATE_NEWER` with the nextStep above. `Start`: a workspace-scoped fixture call on a target not open gets `WORKSPACE_NOT_OPEN` with nextStep naming `workspace.open`, no operation, handler not run. ADR-0027, with the drain bound injected as 200 ms; every fixture handler returns `nil`, never an error, so `completed` and `cancelled` can be told apart: `close` with nothing running in the workspace returns in under 50 ms; `close` while a fixture that honours its context runs in that workspace returns only after the fixture has ended `cancelled` with `OPERATION_CANCELLED`, while a fixture in another workspace runs on; `close` while a fixture that ignores its context runs returns between 200 ms and 1 s, the workspace `closed`, a log line naming the operation, and the operation, still `running`, ends `cancelled` with `OPERATION_CANCELLED` once released although its handler returned `nil`; while that close drains, a workspace-scoped fixture call gets `WORKSPACE_NOT_OPEN` at `Start`, an `open` returns only after the close has, and answers `ready`, and a second `close` returns after the first and completes; `operation.cancel` on the close operation while it drains leaves it to end `completed` with the workspace `closed`; `describe` after `close` gets `WORKSPACE_NOT_OPEN`; `close` of a target not open completes as a no-op; the drain bound wired in production is 10 s. The one-lock rule, deterministically (B1): a workspace-scoped fixture call is held at the test hook inside `Start`, after its open check and before its recording; `close` is called in another goroutine; the test asserts for 200 ms that the workspace is still not `closing` and `close` has not returned (with one lock `close` cannot enter `closing` while `Start` holds it), then releases the hook; the operation then ends `cancelled` with `OPERATION_CANCELLED` and `close` returns after it. With two locks `close` enters `closing`, drains nothing and returns while `Start` is held, and the operation, recorded afterwards in a closed workspace, ends `completed`: that is the mutation that must fail the test. The index (R16): with a `workspaces.json` of `schemaVersion` 2, `open` by root answers `ready`, `open` by the id of a workspace this daemon has not opened ends `failed` with `WORKSPACE_ROOT_INVALID`, the file's bytes are unchanged, the store records `newerVersion` for it, and neither call returns `REQUEST_INVALID_PARAMS`. Seen failing with each decision reversed (close returning at `closing`; no drain bound; an open during `closing` rejected; the check and the recording under separate locks; close's cancel not forced, so a `nil`-returning fixture ends `completed`; a write to a newer index attempted, so `open` fails with the store's error). Then `go test ./internal/schema` fails with exactly the diff below, and `-update` is run only if it is that.

### 6. The supervisor: descriptors, lazy start, readiness, idle shutdown, stop

- Builds: `internal/process`: a descriptor `{id, kind (shared-sidecar | workspace-sidecar), command, args, dir, env, scope (global | workspace:<id>), readiness (a probe on the process's output, never a sleep), idleTimeout, shutdown {signal, timeout}, logSink (a bounded buffer of output lines)}`. `Use(ctx, descriptor)` starts the process on first use (`Setpgid`; stdin a pipe the supervisor holds; stdout and stderr drained), writes its pid record as soon as the pid is known, waits for readiness, and returns a lease; leases are counted; at zero an idle timer runs, and on expiry the process stops if still unused; `Use` fails at once, spawning nothing, when its `ctx` is done, so an operation cancelled by a close and left running past the drain cannot start a sidecar again (ADR-0027); an unexpected exit marks it `failed` and removes its record, and the next `Use` starts it afresh. `Stop(scope)` and `Shutdown()` are explicit stops and ignore leases (idle shutdown alone respects them): the signal to the group, the descriptor's shutdown timeout, `SIGKILL` to the group, reap, record removed. Both run on the descriptors' own timeouts and take no caller context, so an exhausted shutdown deadline cannot skip the `SIGKILL`; step 7's `droidyard stop` check proves this on real processes (level 5). States `starting`, `ready`, `busy`, `idle`, `stopping`, `stopped`, `failed`, readable in process. Every spawn happens on one goroutine locked to its OS thread for the supervisor's life; on Linux each child gets `Pdeathsig: SIGTERM`. With a newer `processes.json`, `Use` fails and spawns nothing (R10). The dummy, test-only, in `internal/process/processtest` (R17): the test binary re-executed in a sidecar mode that prints a ready line, answers each stdin line, appends what it observes (ready, each `SIGTERM`, stdin EOF) to an event file named in its environment, and exits on stdin EOF; options to ignore EOF and `SIGTERM`, to fork a helper into its group, and to write a lot of output.
- Implements: `process-lifecycle.md` §Model (without `health` and `restart`), §Lifecycle states, §Startup (lazy, readiness per process), §Idle shutdown ("never interrupt an in-flight operation"; "auto-restart on next use"), §Shutdown, cancellation and no-orphans (own process group; layer 1 stdin EOF; layer 2 `Pdeathsig` with the locked thread; layer 3 records), §Output handling (bounded buffers); ADR-0021 §Pid records (written at spawn, removed at reap).
- Check: real processes on macOS, `-race`: no process and no record before the first `Use`; the first `Use` returns after the ready line, with a record whose start time matches the live pid; with a lease held past `idleTimeout` the process stays; once released it stops within `idleTimeout` plus a margin, its record removed, state `stopped`; the next `Use` starts a new pid; `Stop` on a dummy that ignores `SIGTERM` and forked a helper leaves neither alive after the timeout, record removed; `Stop` with a lease held stops the process; `Stop(workspace:a)` stops only `workspace:a`'s dummy, while a `workspace:b` dummy and a global dummy keep their pids and records; `Use` with a cancelled `ctx` returns an error and spawns nothing; a dummy killed from outside becomes `failed`, its record removed, and the next `Use` starts it; `Shutdown` stops every process; a dummy writing megabytes is not blocked and the sink holds no more than its bound; with a newer `processes.json` `Use` fails and nothing is spawned; `GOOS=linux go vet ./...` prints nothing, so the `Pdeathsig` and locked-thread spawn path compiles. Seen failing with each decision reversed (idle stop with a lease held; the pid killed instead of the group; the record written after readiness; `Use` ignoring a done `ctx`; `Stop` matching every workspace scope).
- Schema: no change.
- Needs: steps 1, 2.
- Not here: restart policy and health probes, and the per-root `connection.close` of a shared sidecar (with the first shipped sidecar: Not in this milestone); per-operation children such as `logcat` streams (device slice); `process.lifecycle` and `process.output` events (1d); idle-timeout defaults (`process-lifecycle.md` §Open questions; set by the first real sidecar); a workspace going `degraded` when a sidecar fails to start (`process-lifecycle.md` §Startup): its first consumer is a workspace sidecar, the Kotlin LSP, post-MVP, and the shared Gradle sidecar's failure handling belongs to Phase 1.

## Design questions

None open. The first draft (2026-10-02) was `Blocked` on two questions; the owner decided both on 2026-10-03, as new ADRs rather than the amendments to ADR-0020 the drafts proposed.

### Resolved on 2026-10-03

- **Q1, the error codes of `workspace.open`** (steps 3, 4, 5): [ADR-0026](../adr/0026-workspace-addressing-invalid-roots.md). `WORKSPACE_ROOT_INVALID` for a target that is not an existing, readable directory or an id no workspace index holds: the operation ends `failed`, `details {target}`, nextStep "call `workspace.open` with the absolute path of a readable project directory"; ADR-0020's `Start` rejection list is unchanged. `WORKSPACE_STATE_NEWER` for a `workspace.json` of an unread `schemaVersion`: the workspace opens `degraded`, the file is never overwritten, `workspace.open` and `workspace.describe` carry the error in `degradedBy`, nextStep "upgrade droidyard, or delete `<state>/ws/<wsid>/` to reset this workspace". The golden file lists both codes on `workspace.open` and `WORKSPACE_STATE_NEWER` on `workspace.describe` (ADR-0026, `Amended: 2026-10-03`). The decision matches the plan's draft; it was not an amendment to ADR-0020 but a new ADR that "relates to" it.
- **Q2, when `workspace.close` completes** (steps 3, 7): [ADR-0027](../adr/0027-workspace-close-and-reopen.md). `close` completes when the workspace is `closed`; entering `closing` rejects every other workspace-scoped call at `Start` with `WORKSPACE_NOT_OPEN`; operations are cancelled and waited on for up to 10 s (working default), one still running then is logged and left to end `cancelled`, then the workspace's sidecars stop (shutdown timeout, then `SIGKILL` of the group); a close is not cancellable once begun; `open` and `close` of one workspace are serialised. The decision matches the plan's draft. One addition: the 10 s bound is to move to the configuration file in Phase 1 (ADR-0027 §Consequences); step 3 keeps it a constant until then.

The documents that restate these rules were aligned in commit `deccad4`: `workspace-state.md` §Lifecycle names both codes and the close rule, and its open question on reopening while draining is gone; ADR-0021 §Format names `WORKSPACE_STATE_NEWER`; ADR-0020 §Scope and workspace addressing points to both ADRs; each carries an `Amended:` line.

## Readings the steps take

Not questions: each follows from a cited document and is cheap to change. The owner may promote any of them to a question.

- **R1. Trust.** ADR-0015 §5: a root is trusted only if it falls under a configured prefix or through an explicit human act, and "trust on first open" was rejected. 1c reads no configuration (no format exists) and has no human channel (`trust` and `policy.update` are Phase 1), so `trusted` is `false` for every root. No 1c capability runs project code, so `WORKSPACE_UNTRUSTED` has no caller yet.
- **R2. Version `0.2.0`.** 1b kept `0.1.0` because nothing had been released "to a consumer" and nothing was reachable by an agent; the second is no longer true (OpenCode, verified). `capability-api.md` §Error model puts new codes in a minor version, and ADR-0019 §7 detects a stale daemon only by a differing version: a 1b daemon auto-started for OpenCode would otherwise accept a 1c shim's hello and ignore its `root`. The three new capabilities carry `since` `0.2.0`; the protocol stays 1.
- **R3. The CLI's default workspace.** ADR-0020: "the CLI from `--workspace`, else the cwd's root". The shim does not know a capability's scope, and the envelope rejects a workspace on a global call, so the CLI shim sends its cwd's root in the hello (ADR-0019 §7's `root?`, not restricted to MCP), and the daemon's native handler fills `workspace` from it for a workspace-scoped capability whose request names none. "The cwd's root" uses the only root rule documented, ADR-0019 §Sessions.
- **R4. When the bound root opens.** ADR-0019 says "when the MCP session initializes"; `mcp-tool-surface.md` says "when the session starts". The adapter opens it after the hello and before it reads the first MCP message: no client can observe the difference, and the order does not depend on `mcp-go`'s hook timing (level 2 only).
- **R5. Targets.** An envelope `workspace` starting with `/` is a root, canonicalised to an id; anything else is an id. The CLI passes `--workspace` verbatim, since the envelope takes "a workspace id or an absolute project root".
- **R6. Result shapes.** `open` returns the workspace's state ("a no-op returning its state", `workspace-state.md`), the same object as `describe`; `close` returns `{}`, as `operation.cancel` does. The object carries the identity fields of `workspace-state.md` §State model that exist in 1c; `sdkRoot` is added with the SDK subsystem, an additive change.
- **R7. Error lists.** `WORKSPACE_NOT_OPEN` is a `Start` rejection, cross-cutting like `REQUEST_MISSING_WORKSPACE`, so no descriptor lists it. `workspace.open` lists `WORKSPACE_ROOT_INVALID` and `WORKSPACE_STATE_NEWER`; `workspace.describe` lists only `WORKSPACE_STATE_NEWER`, which it carries in a completed result's `degradedBy`, because a root that cannot be opened is never open (ADR-0026 §Decision, as amended 2026-10-03).
- **R8. File shapes.** `processes.json` `{schemaVersion, processes: [{id, kind, workspace?, pid, pgid, startTime, command}]}`, the fields of ADR-0021 §Pid records; `startTime` is the kernel's value as an opaque integer, compared for equality only. `workspaces.json` `{schemaVersion, workspaces: {<wsid>: {root, name, lastOpenedAt}}}`; `workspace.json` `{schemaVersion, root, name, createdAt}`, `name` the root's basename. The recipe's `snapshot` reads pids with `jq '.. | .pid?'`, which works on this shape.
- **R9. `stateProblems`.** ADR-0021 requires corrupt files to be "reported in `system.health`" and names no field: an optional array `{file, problem, movedTo?}`, `problem` `corrupt` or `newerVersion`, in lowerCamelCase per `capability-api.md` §Enum spelling.
- **R10. A newer `processes.json`.** ADR-0021: never overwritten. A spawn the daemon cannot record breaks the no-orphans guarantee, so the supervisor refuses to spawn and the problem shows in `system.health`. No shipped capability spawns in 1c.
- **R11. Reaping waits at most 5 s**, once for all orphan groups together, between `SIGTERM` and `SIGKILL`. ADR-0021 says "wait, then `SIGKILL`" with no figure, and a record has no shutdown timeout. A constant; one wait rather than one per record keeps a start inside the shim's 10 s auto-start retry (ADR-0019 §Processes 4).
- **R12. The dummy sidecar is test-only**, as 1b's fixtures are: ADR-0019 §3 fixes the complete subcommand set, and a debug capability would enter the published schema and the MCP tool list. The recipe's two rows that assume a shipped capability are replaced by step 7's tests, which `verify-daemon` §Keeping it true allows.
- **R13. A failed bound open.** ADR-0020: "A failure does not fail the session: workspace tools then return the error." ADR-0026: the binding "degrades to `WORKSPACE_NOT_OPEN` on every workspace tool until `workspace_open` shows the cause". The adapter keeps no error state (adapters translate only, `capability-api.md` §Mapping to adapters): workspace tools get the core's `WORKSPACE_NOT_OPEN`, and `workspace_open` returns `WORKSPACE_ROOT_INVALID`.
- **R14. Document alignment.** None pending: commit `deccad4` brought `workspace-state.md`, ADR-0020, ADR-0021 and ADR-0026 into line with ADR-0026 and ADR-0027 (Design questions). The first revision's list of stale documents no longer applies.
- **R15. Close's operation.** `workspace.close` is an operation like any other, so `operation.cancel` on it is accepted; ADR-0027 makes the close itself not cancellable, so its handler ignores its context and the operation ends `completed` (under `operation.cancel`, an operation whose handler returns a result ends `completed`: 1b's rule in `internal/capability/operation.go` `run`, which step 3 keeps for `operation.cancel` and overrides only for the forced cancel a close uses).
- **R16. A newer `workspaces.json`.** ADR-0021 §Format: a newer file is never overwritten; ADR-0026 covers only `workspace.json`, and R10 only `processes.json`. The index serves id resolution and recent workspaces (R8), so with a newer index the daemon neither reads nor writes it: `open` by root proceeds and skips the index update; `open` by an id that this daemon has not opened in its life ends `failed` with `WORKSPACE_ROOT_INVALID` ("an id that no workspace index holds", ADR-0026: the unread index holds nothing); `system.health` `stateProblems` shows `newerVersion` for it. Only existing codes are used, and no call returns `REQUEST_INVALID_PARAMS`, which ADR-0026 §Alternatives considered rejects for a target. The alternative, degrading every workspace while the index is unreadable, is the owner's to choose; promote this reading to a question if preferred.
- **R17. Test plumbing.** The helpers of step 2 and the dummy of steps 6 and 7 are modes of the re-executed test binary, implemented in `internal/process/processtest`, a package that only `_test.go` files import (step 8 checks that the built binary does not link it). They talk to the test through files in the test's temporary directory: pids and start times, the dummy's event file (appended, one line per event, so its order is the order of observation), and the release file a held `fixture.sidecar` polls for.
