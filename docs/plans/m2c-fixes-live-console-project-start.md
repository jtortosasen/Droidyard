## Run rules

- K1. `B=~/Library/Caches/droidyard-dev/m2c`. Every daemon runs with `DROIDYARD_STATE_DIR` and `DROIDYARD_CONFIG_DIR` under `$B`, a fresh pair per run. A daemon auto-started by a CLI call inherits that shell's environment (ADR-0019 §8), so **every** `droidyard` invocation of a run, bare ones included, exports both, `ADB=$B/bin/adb`, `ANDROID_AVD_HOME=$B/avd` and `ANDROID_SERIAL=droidyard-m2c-none`, and `system.health` is read first to confirm them; the real state root `~/Library/Application Support/droidyard`, its configuration and the owner's running daemon untouched; the demo daemon under `~/Library/Caches/droidyard-dev/m2b/demo` left alone; the owner's user-level assistant configuration never written.
- K2. Devices: `m1l-phase1-acceptance.md` §Owner's constraints, S2–S7, E1–E7 with `m2c` for `m1l`. Never touch, kill or restart the adb server on 5037; never modify or build in `~/Documents/DopamineControl`; never `uiautomator dump` an owner emulator (every daemon `-tags droidyard_nodump`); owner AVDs may be started and stopped, never wiped or uninstalled from; agent writes only on scratch AVDs, behind the guard copied to `$B/bin/adb` from the `m2b/bin/adb` pattern; never modify the Android SDK (S3's stamp); kill only pids the run started; `ANDROID_SERIAL=droidyard-m2c-none` and no `install*`, `uninstall*`, `connected*`, `device*` task. Scratch AVDs: `droidyard_m2a` (its `.avd` under `~/Library/Caches/droidyard-dev/m2a/avd`, reused in place) and, for step 13, `droidyard_m2c` created with `ANDROID_AVD_HOME=$B/avd avdmanager create avd` from the same installed system image (`ls ~/.android/avd` unchanged after, S3's stamp clean); `$B/avd` also holds a `droidyard_m2a.ini` pointing at m2a's `.avd`, so one `ANDROID_AVD_HOME=$B/avd` lists both. A device run ends with E5's wipe and stop of each scratch AVD it booted; both AVDs are kept.
- K3. Gradle: the sample copied by `git archive` of the commit under test into `$B/g-<run>` (S2), trusted under the run's state only.
- K4. Browser: headless Chrome over CDP with a scratch profile under `$B`, 2a's K3 probe first, the CDP network log kept.
- K5. "An agent" is a scripted `droidyard mcp --no-autostart --root <copy>` session (`verify-daemon` §Drive, MCP): real shim, client `mcp`, no LLM.
- K6. The implementer never runs adb, an emulator, Gradle, a browser or a native dialog; level-4 and level-5 runs are the main session's.

## Design questions

Each has a recommendation the main session may apply as Delegated (owner: "you decide"); each becomes an ADR at the start of the step that implements it.

### Q1. How does the console reach the UI while a build runs?

- Blocks: steps 3, 9
- The documents say: `build.output` is designed with no producer (`capability-api.md` §Events, register); `gradle.md` §Output: batches every 100 ms, `consoleRef` published only at the end; ADR-0041 and ADR-0043 set the pattern. Nothing defines the payload.
- Draft decision, now ADR-0044:
  1. **Capability** `build.watchOutput`: command, **workspace-scoped**, streaming, audience all, not long-running, since `0.16.0`; params `{}`; result `{subscriptionId, builds: [{buildId, consoleRef, offset}]}`, the workspace's running builds with each console's size taken **after** the subscription opened. The client reads `[0, offset)` with `artifact.read`; the rest arrives as events. One subscription follows every build of the workspace, any client's.
  2. **Events**, topic `build.output`, type `lines`: `{buildId, consoleRef, offset, stream, lines}`; `stream` is `stdout`, `stderr` or `droidyard` (the connector notice and the cap marker). The console holds **whole lines only**: a line that does not fit under the 32 MiB cap is dropped whole and counted in `consoleDropped` (as `buildSink.Output` counts today), so the marker starts its own line and no rune is split. Every line appended is published once, in order: the prefix plus the events equal the console. Project output, not untrusted (ADR-0015 §1).
  3. **Delivery** as ADR-0043 §3: a seq, never the ring, offered to every watch of that workspace, not through `events.subscribe`; after `events.gap` the client reads from its last offset.
  4. Off MCP (ADR-0010): agents keep `artifact.read` after the build. `0.15.0` → `0.16.0`.
- Alternatives considered: **polling `artifact.read`** — no contract change, but the owner's "Logcat-grade" rules polling out and the ref is unpublished until the end; **an `events.subscribe` topic** — no snapshot for a tab opened mid-build, no published payload, a busy build flushes the ring; **a per-build watch** — one subscription and one start race per build, learned from `operation.state`; **lines on `operation.progress`** — rejected by m1d.

### Q2. How does a user reach a project without typing a path?

- Blocks: steps 4, 10, 12
- The documents say: one daemon per user hosts every workspace (ADR-0019, whose rejected per-root option left "recent workspaces" no home); `workspaces.json` is "recent workspaces" (ADR-0021 §Layout); trust is a human act "(the UI, or `droidyard trust`)", never on open (ADR-0015 §5); `policy.update` is human-only with `ifRevision` (ADR-0032 §5); the human audience is "the one deliberate exception", for policy (ADR-0015 §6); a page cannot learn a native path.
- Draft decision, now ADR-0045:
  1. **Entry points.** `droidyard` with no subcommand runs `ui`. `ui` looks for a project from its cwd by the MCP binding's rule (nearest ancestor holding `settings.gradle(.kts)`); found, it opens it (`workspace.open`, client `cli`: no project code, no trust) and the browser at `/#token=<t>&w=<wsid>`; not found, at `/#token=<t>`, the picker. Auto-start as ADR-0019 §4; no new subcommand.
  2. **One daemon, one tab per project.** ADR-0019 unchanged. A tab's project is the fragment's `w` (an id, never sent to a server); the token moves to `sessionStorage` and `w` stays, so a reload stays. The picker is the page without `w`, switching in the same tab; several projects are several tabs.
  3. **`workspace.watch`**: command, global, streaming, audience all; result `{subscriptionId, workspaces: [{id, name, root, lastOpenedAt, state, trusted}]}`, the index merged with live states, newest first, at most 50, taken after the watch's subscription opened. Its events are a **new ring-less topic `workspace.state`**, type `state`, payload `{state, degradedBy?, name, root, trusted}`, published beside every `workspace.lifecycle` publish and offered to every `workspace.watch` subscription (ADR-0043 §3); `workspace.lifecycle` stays as it is (`events.subscribe` serves it and the registry reserves it). Per-workspace transitions are published in order under the workspace's transition lock, so snapshot plus events converge. `lastOpenedAt` is refreshed on every open, an already open workspace included. Streaming keeps it off MCP and the agents' budget (ADR-0036), as ADR-0043 §1; it also answers "a workspace opened before the tab".
  4. **`workspace.chooseRoot`**: the macOS folder dialog (`osascript` `choose folder`) run by the daemon; elsewhere unavailable with the reason, and the UI falls back to the typed field. Query, global, stateless, long-running, 5 minutes, one at a time; `{root}` (the binding's rule applied to the choice) or `{dismissed: true}`; error `WORKSPACE_DIALOG_FAILED`. **Audience human**: it puts a window on the user's screen and its answer is a human's choice, so an agent may not raise it; ADR-0015 §6's "one deliberate exception" gains this second use, and policy remains the only thing it guards against self-authorisation. Consequence: a remote browser (ADR-0006's tablet, once LAN exists) would raise the dialog on the host; the directory browser wins there.
  5. **Trust from the UI**: an untrusted project says what trusting means and offers Trust, a `policy.update` of `trust.roots` (the list read plus this root) with `ifRevision`; the UI then reads `workspace.describe` again (trust changes publish no event). Opening, the CLI entry and the project file never trust.
  6. No HTTP route or rule changes; every action is a capability.
- Alternatives considered: **a directory-browser capability** (any directory's subdirectories, human-only) — cross-platform and testable, but a read surface over the whole disk and a file-manager UI; it wins if step 2 D fails, on Linux, or for a remote browser; **Linux `zenity`/`kdialog`** — no host here runs them; a later minor change; **a typed path with completion** — the owner's "no paths"; **the root in the URL** — a path in history and every copied link, while the id resolves through the index (ADR-0026); **one daemon per project** — ADR-0019's rejection stands; **a `workspace.list` query** — an MCP tool or a stretched audience (ADR-0043); **trust on open or from the CLI entry** — rejected by ADR-0015 §5; **a native app** — owner: not now.

### Q3. Where do the project's UI choices live?

- Blocks: step 11
- The documents say: ADR-0021 §Location: state "never inside the project tree", `.droidyard/` rejected; `ws/<wsid>/workspace.json` was to hold "selected variant, preferences"; ADR-0037 §Consequences: files in the project are the user's asked-for files; the owner asks for a per-project file in the folder, as IDEs keep one.
- Draft decision, now ADR-0046:
  1. **`<root>/.droidyard/project.json`**, `schemaVersion: 1`: `{build: {module, variant}, device: {avd} | {serial}, applicationId}`; unknown keys kept; a newer version, or a file that does not parse, is treated as absent and never overwritten (shown as such). A directory, as `.idea/` and `.vscode/`.
  2. **Read and written by the UI** with `file.read`/`file.write` (the daemon stays the only writing process), on the first change, never on open: opening leaves the tree untouched. Last writer wins; no capability interprets it. A write that fails (a read-only checkout, ADR-0021's concern) keeps the choice for the tab and shows the failure.
  3. **It only preselects.** A module, variant, AVD or serial the daemon's lists lack is ignored; `applicationId`, which no list holds, is used only for launch and logs after a click, below D20's build output; nothing runs from the file without a click, and it never carries trust, policy, device admission or tool keys (ADR-0031, ADR-0032): a repository shipping one gains nothing.
  4. Everything else ADR-0021 keeps out of the tree stays out. Git visibility is the user's (owner: not now). It replaces m2b D10.
- Alternatives considered: **`ws/<wsid>/workspace.json`** — the choices would not travel with the project; **a typed capability** — a contract and an agent tool for UI preferences with one consumer; **`localStorage`** — per profile and origin, D10's limit; **one root file `.droidyard.json`** — valid, with no room for a second file.
