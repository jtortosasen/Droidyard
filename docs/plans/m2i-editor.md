## Delegated decisions

- D1. **One version**: step 2 moves `0.19.0` → `0.20.0`; nothing else in 2i changes the contract.
- D2. **CSP**: the editor and the merge view are mounted in an open shadow root on their host element and given it as `root`, so style-mod uses constructed, adopted style sheets, which the CSP's `style-src` does not govern (assumption: Unverified; step 3 settles it at level 4). The CSP and `httpapi.go` do not change (m2a D6). Theme values reach the shadow tree as inherited custom properties. No decoration or theme sets a `style` attribute (classes only). If step 3 shows the sheets refused, the plan stops there with a design question: a per-response nonce through `EditorView.cspNonce`, which changes `http-websocket.md` rule 7 and needs an ADR.
- D3. **One seam**: only `web/src/lib/editor/cm/` imports `@codemirror/*` or `@lezer/*`; the rest of the app reaches it through one dynamic `import()` and a small interface (mount, set document, read-only, reveal position, diagnostics, destroy), so the editor stays replaceable (ADR-0009 §Consequences). Each language is its own dynamic import.
- D4. **Dependencies**, exact versions chosen at the step (K6): step 3 `@codemirror/state`, `@codemirror/view`, `@codemirror/language`; step 4 `@codemirror/legacy-modes`, `@codemirror/lang-java`, `@codemirror/lang-xml`, `@codemirror/lang-json`, `@codemirror/lang-markdown`, `@lezer/highlight`; step 6 `@codemirror/commands`, `@codemirror/search`; step 7 `@codemirror/merge`; step 8 `@codemirror/lint`; step 5, only if the Lezer grammar is vendored, `@lezer/lr`. Not the `codemirror` bundle package, not `@codemirror/autocomplete` (no completion, no auto-closed brackets: not in O5).
- D5. **Read-only** with a banner naming why: a binary file (today's placeholder), a file over 512 KiB, a read capped at 2 MiB (D26), a read without a `revision` (over 8 MiB, Q1), mixed line endings or a lone CR. A file whose breaks are all LF or all CRLF is edited with that separator (`EditorState.lineSeparator`; a file with no break gets LF); an `EditorView.clipboardInputFilter` turns pasted breaks into it, and Compare's editable side is built with the tab's own separator, so a save writes the bytes it read plus the edits. A BOM is kept as text.
- D6. **A consistent read**: every page of one read carries the same `revision` (when present). A complete read with a revision is also checked whole: the SHA-256 of the joined text's UTF-8 (WebCrypto) must equal it. A page revision that differs starts the read again, at most three times, then fails with a message; a whole-file mismatch with every page's revision equal (a final line cut mid-rune comes back with U+FFFD) opens the file read-only instead. A complete, checked read's revision is the buffer's base; a capped or revision-less read is read-only (D5) and has no base.
- D7. **Save**: Mod-s (Cmd on macOS, Ctrl elsewhere) while the editor has focus, as `file.write {path, content, ifRevision: base}`, one save at a time (a Mod-s during one is queued after it, with the new base); the client hashes `content` before sending, so the save's revision is known in flight. Refused with a message, without a call, when the content is over 512 KiB or the request's JSON over 1,000,000 bytes (`MaxBody` less the envelope). Edits typed during a save stay dirty. The first edit makes a preview tab permanent. One editor state per open tab (its undo history included) survives switching tabs, and follows the tab through a rename or move in the tree (m2g D57): the models are re-keyed by path prefix before the tabs move, base and history kept (a rename keeps the bytes). A move can only meet an open tab whose file is gone (`file.move` never replaces): `FileOps` refuses, before any call, a move, paste or Undo whose target is, or holds, an open dirty tab, with a message; otherwise the moved model takes the path and a clean model at the target is dropped. A `created` whose revision equals the base clears a `deleted` mark (a move's own events). Closing a dirty tab, leaving the project with any dirty buffer (the router's navigation, the projects panel, Back and Forward: the URL is restored and the dialog asks), or unloading the page asks first: a dialog with Save, Don't save, Cancel (`beforeunload` for an unload).
- D8. **External change**: a `modified` or `created` event, or a re-sync, for an open file re-reads it (D6). A revision equal to the base or to the in-flight save's → nothing (our own save's echo); a read without a revision is never an echo and replaces a clean read-only view. Clean → the text swaps silently, the selection clamped and the scroll kept. Dirty → never reloaded; a bar: Reload (the disk's text and revision; disabled when the disk side is `absent`), Keep mine (the disk's revision, or `absent`, becomes the base, so the next save replaces or re-creates it knowingly; disabled when the disk read has no revision, since the editor never sends `file.write` without `ifRevision`), Compare (a `@codemirror/merge` view in the same pane, the disk read-only beside the editable buffer; leaving it keeps the buffer's edits). A save answered `FILE_REVISION_CONFLICT` re-reads and shows the same bar. `deleted` keeps today's banner; a save then conflicts (`absent`) and shows the bar. Step 6 already never reloads a dirty buffer; step 7 adds the bar.
- D9. **Editing built-ins**: CM6's default, history, search (find and replace, go to line), fold keymaps; `indentWithTab`, with Escape then Tab leaving the editor (CM6's documented escape); multiple selections and rectangular selection; line numbers, fold gutter, active line. No Vim or Emacs keymap, minimap or wrap toggle.
- D10. **Problems to editor**: a record is locatable when its `file` is a relative path neither `external` nor `merged`, or when it is `merged` with a relative `resolved` file (the extractor already makes an inside one relative, `extract/parse.go`); any absolute path is not locatable (no prefix matching against the root's spellings); otherwise its row has no link. A click opens the file as a tree click does (a preview tab), puts the cursor at line:column (1-based; no column → the line's start; past the end → clamped), scrolls it into view and reveals it in the tree. The last build's records for an open file are `@codemirror/lint` diagnostics (`setDiagnostics`, `lintGutter`, no lint source), messages as text (no `renderMessage`), replaced at each new build result, their positions following edits.
- D11. **The spike's rule**, fixed before it runs: a checklist file of Kotlin constructs (C1 string templates `"$a"` and `"${a.b}"`; C2 a raw `"""` string over lines holding `"`; C3 annotations `@Composable`, `@OptIn(X::class)`; C4 soft keywords used as names, `val data = 1`, `value`, `by`; C5 `suspend fun`, `fun interface`, `inline fun <reified T>`; C6 nested block comments; C7 `0xFF_FF`, `1_000L`, `1.5e3f`; C8 backticked names and `::ref`; C9 KDoc), each a position whose expected highlight tag is written beside it. The Lezer grammar is adopted only if it passes every item the legacy mode passes and at least three more, parses every `.kt` and `.kts` file in `samples/golden` with no error node, and parses a generated 10,000-line file (the golden Kotlin repeated) within 300 ms in Node. Otherwise the legacy mode stays.
- D12. **Colours**: syntax tokens `--syn-*` in `tokens.css` for both schemes; one `HighlightStyle` refers to them by `var()`; `cm/` holds no colour literal.

## Design questions

### Q1. What precondition does `file.write` take?

- Blocks: steps 2, 6, 7.
- The documents say: `files.md` defers conditional writes (register row 143); ADR-0032 §5 gives `policy.update` an `ifRevision` (SHA-256 hex of the bytes, `absent`, `POLICY_REVISION_CONFLICT`); nothing for `file.*`.
- Draft decision, a new ADR (Delegated):
  - Context: an editor buffer and agents write the same files; last writer wins today, so a save can erase an agent's write and an agent a user's save.
  - Decision: (1) `file.read` returns `revision`, the lowercase SHA-256 hex of the whole file read to its end through the page's own descriptor, on every page, omitted for a file over 8 MiB (a page should not cost a large hash). (2) `file.write` takes optional `ifRevision`: a revision, or `absent` (the file must not exist). The daemon opens the target without blocking and hashes it immediately before the rename; a target over 8 MiB is `FILE_TOO_LARGE` (not hashed: it has no revision to compare); a mismatch is `FILE_REVISION_CONFLICT`, nothing written, `details {path}`, the current revision in `cause` only, next step "call file.read and apply the change again" (an agent is sent to read, never told to drop the guard). A conditional write whose target already holds exactly `content` succeeds without writing, so a retried conditional write stays idempotent. (3) `file.write` returns `revision`, the hash of `content`, never a re-read. (4) Every `file.write` on one root holds one mutex from the compare to the rename. (5) Without `ifRevision` nothing changes. API `0.20.0`, additive.
  - Consequences: agents get the protection by passing `file_read`'s revision; about 80 more bytes per `file_read` result (ADR-0036); a writer outside the daemon landing between the hash and the rename is still overwritten (a register row); a page's hash costs up to 8 MiB of reading (benchmark at step 2).
  - Alternatives considered: **`modTime` and `size`** (no `file.read` change): coarse-mtime volumes and mtime-preserving tools (`cp -p`, `rsync -t`, `touch -r`) make a changed file look unchanged, the very loss to prevent, and a model must echo a nanosecond timestamp exactly. **An opaque token of inode, size, mtime and ctime**: cheap, but identical content conflicts, whether a rename updates ctime differs by OS (unverified), and it departs from `policy`'s revision. **A lease or lock held by the editor**: writers outside the daemon ignore it. **A client-side re-read before saving**: a round-trip window instead of microseconds, and agents get nothing. **A revision of the page only**: says nothing about the whole file a write replaces. **Policy's order, the revision checked before the no-op** (`readTop`): a retried write whose first attempt landed would then conflict with itself; identical bytes lose nothing, so the no-op wins here. **The current revision in `details`**: a blind retry with it would overwrite without a read, and `details` only grow (`capability-api.md` §Error model); `cause` still shows it, as policy's does, as text not offered as a field.

## Changes

- Step 7 (Delegated, from the verifier's B1): D8's "clean → the text swaps silently" also requires no redo stack and no held version; a silent take and Reload are undoable history events, so Cmd+Z after an agent's write reverts it locally and leaves the buffer dirty against the agent's revision (a later save overwrites it knowingly, through a valid `ifRevision`, as VS Code and IntelliJ do); a separator change rebuilds the state and resets the history. Keep mine on a buffer undone to clean makes it dirty against the disk's text. A binary disk version is held with Compare off. The bar is in `Viewer.svelte`, not `Editor.svelte`.
- Step 6 (Delegated): Kotlin and Groovy fold at braces (`braceFold` in `cm/languages.ts`): the legacy modes give no folding, so O5's folding would have worked only in XML, JSON and Markdown. Keep both and duplicate are refused only for an open dirty tab marked deleted in the target folder (a live tab's path is taken, so the daemon's free name cannot be it); a deletion whose event has not yet arrived is the residual window.
- Step 2, the verifier's round (Delegated, before 0.20.0 ships since tightening later would break callers): an explicit `"ifRevision": null` is refused, as `policy.update` refuses it; `ifRevision: absent` against an existing file over 8 MiB is `FILE_REVISION_CONFLICT`, settled by existence, not `FILE_TOO_LARGE`. Recorded as [ADR-0059](../adr/0059-file-write-revision-null-and-absent.md) at the close (the close verifier's finding a).
