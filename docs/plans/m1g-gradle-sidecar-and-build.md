## Readings

- R1. **API `0.6.0`**, bumped by step 4, the first step that changes the schema (`capability-api.md` §Discovery and versioning: additive changes are minor).
- R2. **Classification and annotations** follow `capability-api.md` §Classification of the MVP surface; `mcp-tool-surface.md` §The MVP tool surface; `project.modules`, `project.variants`, `build.tasks` W/Q/LR; `build.assemble` W/C/LR, idempotent, not destructive ("replaces only its own, rebuildable outputs"); `build.run` W/C/LR, destructive, not idempotent; `build.errors`, `build.lastResult` W/Q, no `Resource`; `device.install` W/C/LR, not destructive ("`-r` replaces the app and keeps its data"), not idempotent; `device.uninstall` G/C, destructive, not idempotent. `[gradle]` for the seven Gradle ones, `[adb]` for the two device ones.
- R3. **No untrusted field is new**: consoles and build records are project content (ADR-0015 §1); `DEVICE_INSTALL_FAILED`'s cause carries only the `INSTALL_FAILED_[A-Z_]+` token.
- R4. **Trust is decided at the re-check** (`Authorize`), since it reads the configuration file and `Start` does no I/O (ADR-0020, as amended 2026-10-04 for device state). Nothing is spawned before it passes (ADR-0015 §5).
- R5. **Locks** (`core-runtime.md` §Concurrency): `build.assemble`, `build.run` hold the scheduler key `gradle.root:<wsid>`; every TAPI call holds the client's per-root lock, context-aware; `project.*`/`build.tasks` with a cached model while the root is busy answer from the cache with `stale: true` if the fingerprint changed (`gradle.md` §Concurrency). `device.install` and `uninstall` hold `device.write:<serial>`.
- R6. **Nothing a caller sends reaches Gradle or a device shell unchecked**: `module` matches `^(:[A-Za-z0-9_.-]+)+$`, `variant` `^[a-z][A-Za-z0-9]*$`, each `build.run` task `^:?[A-Za-z0-9_][A-Za-z0-9_:.-]*$` (no leading `-`), `applicationId` `launch.go`'s pattern.
- R7. **No new Go module dependency.** New state, configuration and cache files: ADR-0021 §Layout's `ws/<wsid>/builds/` and `artifacts/`, D1's `config.json`, D5's cached jars. New error codes: the documented `WORKSPACE_UNTRUSTED`, `BUILD_OUTPUT_NOT_FOUND`, `_STALE`, `_UNSUPPORTED`, `DEVICE_INSTALL_FAILED`, and D9's.

## Delegated decisions

Taken under the owner's standing instruction; each can be reverted.

- D1. **Configuration file, trust only.** `config.json` in the configuration directory: `DROIDYARD_CONFIG_DIR`; else, under an explicit `DROIDYARD_STATE_DIR`, `<state>/config/` (one variable isolates a run, ADR-0021 §Location; as D5 does for the cache); else Linux `$XDG_CONFIG_HOME/droidyard` (default `~/.config/droidyard`), macOS `~/Library/Application Support/droidyard-config/`, a sibling of the state root, never inside it (ratification: "separate from state, so that deleting state cannot grant or revoke trust"). Shape `{"schemaVersion": 1, "trust": {"roots": [], "prefixes": []}}`, absolute canonical paths; trusted if equal to a `roots` entry or under a `prefixes` entry at a path-component boundary. Unknown keys kept on rewrite and ignored. Missing → nothing trusted; unparseable → nothing trusted, the error's cause naming the file and the parse error, never renamed or rewritten (user configuration, not state). Every other key waits for the full specification. A new ADR plus `Amended:` lines on ADR-0021 and ADR-0024 (the macOS location), by the main session with step 3. **A departure: the owner should see it.**
- D2. **`droidyard trust <root>`** canonicalises the root as `workspace.open` does and adds it to `trust.roots`: under an exclusive `flock` on `config.json.lock`, re-read, then the store's atomic write, so concurrent runs lose nothing; no daemon involved, no auto-start. The daemon re-reads the file (size and mtime) at each trust check, as a hand edit is picked up (ADR-0015 §6). ADR-0019 §3 says the subcommand goes "over `policy.update`", which does not exist yet, and §4 auto-starts it: `Amended:` line covering both, by the main session with step 3. No `untrust`: a hand edit. **A departure: the owner should see it.**
- D3. **Untrusted call**: `WORKSPACE_UNTRUSTED`, nextStep "ask the user to run `droidyard trust '<root>'`"; `workspace.open`/`describe` report `trusted` from D1.
- D4. **Sidecar packaging.** Kotlin (ADR-0017), JVM target 17, in `sidecar/` (`core-runtime.md` §Package layout): `src/`, `build.sh` (compiles with `$KOTLINC`, else Android Studio's bundled `kotlinc`; fetches the Tooling API (newest stable 9.x on repo.gradle.org, recorded) and `slf4j-api` with pinned SHA-256 into a cache), two jars checked in and embedded by `sidecar/sidecar.go` with their SHA-256 pinned by a test and checked before each launch: `gradle-sidecar-deps.jar` (Tooling API, `slf4j-api`, Kotlin stdlib; changes only with a version bump) and `gradle-sidecar.jar` (our classes, small); entries sorted, timestamps fixed; the `kotlinc` version recorded beside the digests (the ADR-0029 pattern); the reproducibility test skips, naming both versions, when the host's `kotlinc` differs from the recorded one. The Go build needs no JVM. **Any later protocol change rebuilds with `build.sh`, updates the digests and reruns step 1's opt-in test.** `Amended:` line on ADR-0017 by the main session with step 1.
- D5. **The jars run from the cache directory**: `$XDG_CACHE_HOME/droidyard` / `~/Library/Caches/droidyard`, or `<state>/cache/` under an explicit `DROIDYARD_STATE_DIR`, named by their digest, written atomically when absent or different. ADR-0012's 2026-10-04 amendment left this location "decided with that producer, as an ADR-0021 amendment": the main session writes it with step 5.
- D6. **Framing**: JSON-RPC 2.0, one message per line; stdout carries the protocol only (the sidecar points `System.out` at stderr at start and writes the protocol to the original stream), stderr goes to the supervisor's log sink. The sidecar caps each failure's message and description at 8 KiB, a tree at 200 nodes, and any single console line at 64 KiB (a marker, the dropped bytes counted), so no build output can produce an over-long message; a line over 1 MiB is a protocol error: the client kills the sidecar and fails the call `BUILD_SIDECAR_CRASHED`, cause "protocol line over 1 MiB". `gradle.md` §Protocol says so in step 1's change.
- D7. **No JSON library in the sidecar**: a minimal hand-written codec, round-trip tested against the Go client for control characters, backslashes, quotes, non-ASCII and lone surrogates (decoded as U+FFFD).
- D8. **Fingerprint**: size and mtime of `settings.gradle(.kts)`, every `build.gradle(.kts)`, `gradle.properties`, `local.properties`, `gradle/*.toml`, `gradle/wrapper/gradle-wrapper.properties`, every file under `buildSrc/` and under any directory holding its own `settings.gradle(.kts)` (an included build such as `build-logic/`), skipping `build/`, `.gradle/`, `.git/`, bounded to 20 000 entries; the model cached in memory per `(root, fingerprint)`.
- D9. **New error codes**, documented in `gradle.md` §Failure modes and `adb-device.md` §Failure modes by the step that adds them: `BUILD_SIDECAR_UNAVAILABLE` (no JVM ≥ 17, with `details.candidates[] {source, path?, rejected}`; a start, handshake or `protocolVersion` failure), `BUILD_SIDECAR_CRASHED` (it died serving the call, or broke the protocol), `BUILD_GRADLE_UNSUPPORTED` (below the 8.0 floor, naming floor and version; its nextStep omits ADR-0018 rule 3's escape hatch, `gradle.allowBelowFloor`, until the configuration specification defines the key: a flagged departure), `PROJECT_MODEL_FAILED` (configuration failed; Gradle's root failure message as cause), `BUILD_NOT_FOUND` (an unknown `buildId`, or no finished build), `DEVICE_UNINSTALL_FAILED`.
- D10. **Result shapes.** `build.assemble`/`build.run`/`build.lastResult` return the compact record: `{buildId, request, outcome, startedAt, finishedAt, durationMs, gradle {version, source, daemonJavaHome}, profile, missingCapabilities[], validation, agp: "unknown", kgp: "unknown", taskSummary, failedTasks[], errorCount, warningCount, errors[] (first 5), outputs[], extraction, consoleRef, warnings?}`; `build.errors {buildId?, includeWarnings?}` returns the merged problems with `gradle.md`'s caps and, when unrecognised, the labelled tail. The persisted record also keeps `tasks[]`, `failures[]` and the output-path index.
- D11. **`build.run {tasks[]}` only** (1–20 tasks, R6); no `args`, which `gradle.md` §Open questions leaves open.
- D12. **AAPT2 merged paths** (ADR-0022 §Known open item): option 3 always (the path verbatim, `merged: true`); option 2 when exactly one file under the failing module's `buildDir` matches the merged-resource layout step 2 records: `excerpt`, that line, at most 300 characters. If step 2 finds the merged file absent after a failed link, option 3 alone, recorded under Changes. `Amended:` line on ADR-0022 by the main session with step 6.
- D13. **Persistence.** A build record is written when the build finishes (`ws/<wsid>/builds/<buildId>.json`, `index.json`, `schemaVersion` 1); a running build is its operation. Its console is a durable artifact `ws/<wsid>/artifacts/<buildId>.log`. Console files no record owns are deleted when the workspace is first opened after a start (ADR-0012 says "at startup"; the registry is loaded at open, and an unopened workspace's orphans harm nothing until then). The durable ref encodes the class, the workspace and the build id, never a path; it resolves after a restart without the workspace being open; a well-formed one whose file is gone is `ARTIFACT_EXPIRED` (nextStep: build again). Retention per `gradle.md` (50 builds or 7 days), applied at each finish.
- D14. **Real-Gradle tests are opt-in**: they run with `DROIDYARD_GRADLE_TESTS=1` and skip otherwise, saying the level they would reach, so `go test ./...` stays fast; each step's check names the command, and S5 applies.
- D15. **Scratch location**: §Scratch rules S1, durable across reboots (not `/tmp`).
- D16. **Fixtures from OwnerAppA** are trimmed excerpts: only the lines a golden test reads, with the scratch path rewritten to `/w/dc`; no other project content (`mvp.md`: too personal to pin in CI).
- D17. **Profile without the probe**: `profile` from the Gradle version (`full` ≥ 8.13, `degraded` 8.0–8.12) and dropped to `degraded` when a gated call throws `UnsupportedMethodException`, with `missingCapabilities[]` naming it (ADR-0018 §Capability profile values); the Problems subscription only from Gradle 8.12 (rule 1); `validation: untested` for every version (no CI row yet); AGP and KGP `unknown`, so the console extractor is primary for every tool (ADR-0018 §Plugins).
- D18. **`device.uninstall`**: `pm path <id>` first; absent → completed `{applicationId, uninstalled: false, reason: "notInstalled"}`; else `adb uninstall`, `Success` → `uninstalled: true`, a `Failure […]` → `DEVICE_UNINSTALL_FAILED` with the bracketed token.
- D19. **No wrapper**: proceed, `gradle.source: "connector"` and a warning naming it and saying the Tooling API's own Gradle distribution is used, downloaded on first use (about 150 MB) (`gradle.md` §Failure modes: "report it"). **Task not found**: Gradle's own failure, a failed build (no near-matches).
- D20. **Sidecar crash**: the call fails `BUILD_SIDECAR_CRASHED`, every root with a connection is marked `degraded` with that error, cleared by the next successful handshake; the next call restarts it.
- D21. **Progress**: `operation.progress {done: tasks finished, message: the task running}`.
- D22. **JVM discovery** skips the configured path (no key yet, D1) and uses `gradle.md` §Sidecar JVM discovery 2–5 on the daemon's environment (environment source: inherit). The `gradle` requirement is available when a JVM ≥ 17 is found (the jars are embedded); `system.capabilities` and `system.health` report the JVM and its source, or every rejected candidate.
- D23. **Emulator**: E8.
- D24. **Console cap** 32 MiB per build; past it a marker line and a count of dropped bytes in the record.
- D25. **Staging, adjusted.** ADR-0017 staging 0 puts S1 and S3 "before sidecar code". Here S1 run 2 uses step 1's sidecar as its "minimal TAPI client" (`gradle.md` §Spikes), guarded by step 2's stop conditions; S3 moves to staging 3, with the probe it gates; and the generic model is fetched as TAPI's `GradleProject` and `BuildEnvironment` models, without the `BuildAction` of ADR-0023 §Decision 1, until the probe lands (a `BuildAction` without the probe adds daemon-side code and proves nothing more). `Amended:` line on ADR-0017 and a note on ADR-0023 §Decision 1, by the main session with step 1 (the first sidecar code), beside D4's. **A departure: the owner should see it.**
- D26. **No console tail in build results or their MCP rendering.** `gradle.md` §Output (ratified) and `mcp-tool-surface.md` §Images and artifacts say MCP renders a bounded tail; ADR-0022 §Decision 4 makes the labelled tail of an unrecognised failure the only raw tail. Here a build result renders as its compact record; the agent reads the console with `artifact_read {ref, offset: -16384}` and the errors with `build_errors`. Reason: tokens on every build call, and errors already structured. Both documents are reconciled at the close. **A departure: the owner should see it.**
- D27. **The console is not exposed while the build runs** in this milestone: no result or progress carries `consoleRef` before the build finishes (ADR-0020's operation view has no field for it), although `gradle.md` §Output: control vs. volume (ratified) and ADR-0012 promise reading it while it grows. The store reads growing artifacts (step 4); exposing the ref early lands with the `build.output` topic. **A departure: the owner should see it.**
