## Delegated decisions (owner, 2026-10-21)

Each has a recommended option, taken under the owner's standing instruction; ADR-0122 records them with their alternatives.

- **D1. A CLI connection carries streams.** Every native socket connection gets an `event.Session`, as a WebSocket does; a streaming capability called over it answers its response envelope, then its events as lines `{"subscriptionId","event"}` (ADR-0055's frame), never before that response is written; closing the connection closes the session, which releases every stream it owns (`event.Session.Close`). Supersedes in part ADR-0019 §Sessions ("the shim and `droidyard call` connections cannot subscribe"), ADR-0010 §Decision (as ADR-0108 did for a foreground share), ADR-0041 §7 ("the CLI and `POST /v1/call` get `SESSION_REQUIRED`") and ADR-0113 §6 (`device.watchUiRecordings` "web only"). MCP and plain HTTP keep `SESSION_REQUIRED`. Consequence, accepted: an agent's own shell can now run a streaming command (`droidyard device watch-logs`), which returns only at its stream's `stopped` or when the shell tool's timeout kills it; agents keep `device.logs` (ADR-0041 §7's reason), and a killed CLI releases its stream (below). Frame writes carry no deadline (a paused pager is legitimate; the subscription's bounded queue overflows to `events.gap`): `Daemon.Shutdown` already closes every native connection after its grace (`daemon.go:478-487`), which ends a blocked write. Rejected: the CLI as a WebSocket client (the upgrade's mandatory `Origin` would have to be forged, and every call would show as `ui`); polling queries (no capability exposes a stream's lines as a query).
- **D2. Command spelling.** `droidyard <domain> <verb>`: the domain as registered, the verb in kebab case (`uiTree` → `ui-tree`). Matching ignores case and hyphens, so `uiTree` works too, and the canonical one-word name (`droidyard device.list`), which every `nextStep` uses, runs the same command. A test refuses two verbs of a domain, or two parameters of a capability, that normalise equal.
- **D3. Flags from parameters.** A top-level parameter is `--<kebab name>`, matched like D2. String, integer, number, enum: one value (`--x v` or `--x=v`), parsed to the schema type, an enum checked against its values. Boolean: `--x`, `--x=false`. Array of scalars: the flag repeated, one element each (never comma-split: paths hold commas). Object whose properties are scalars or arrays of scalars: dotted flags one level deep (`--build.module :app --build.variant debug`, `--target.text OK`). Everything else (arrays of objects, open maps, `oneOf`, deeper objects such as `target.within`) only through `--params <json>`, and the verb's help lists it as such. No positional arguments on derived commands.
- **D4. `--params` and flags together.** `--params` is the base object; each flag sets its key, a dotted flag its subkey inside the object `--params` may already hold (`--target.text OK` with `--params '{"target":{"within":{…}}}'` merges); a key or subkey both set is a usage error (exit 2), never a silent precedence. A required top-level parameter missing after both, and after D6, is a usage error before any daemon is dialled or started.
- **D5. The CLI's own flags.** `--json`, `--params`, `--no-autostart`, `--help`/`-h` on every derived command; `--workspace` (the envelope, default the cwd's project root as today) only on workspace-scoped ones, where no capability has a `workspace` parameter; on a global capability a `workspace` parameter (`session.release`, `workspace.forget`, `workspace.show`) is `--workspace`; `--detach` (print the operation id) only on long-running ones. A test over the shipped registry fails on any collision between these and a parameter's flag (today none: `hosting.share`'s `detach` is not long-running).
- **D6. `ANDROID_SERIAL`.** On a derived command whose `device` parameter is **required**, an absent `--device` (and no `device` in `--params`) takes `ANDROID_SERIAL` when set (the 2026-09-29 ratification). An optional `device` is never filled: absent means something there (`device.uiRecordings`: every device). `droidyard call` stays verbatim. The verb's help names the fallback.
- **D7. Output.** Human by default: (a) the descriptor's `Text` renderer (ADR-0036 Decision 2) when it renders the result decoded into its `Result` type (`capability.TextOf` accepts `*T`); (b) otherwise a generic renderer from the result's JSON in field order: an object as aligned `key  value` lines, an array of flat objects as a table (columns the first row's scalar keys), nested values summarised (`{…}`, `[n items]`), an empty array `(none)`; every string with a control, format or line-break character written through `capability.Quote`, so no device text puts a raw control character on the terminal, and in a response marked untrusted (D8) every string, as MCP's text quotes every untrusted string (ADR-0036 Decision 2). A long-running command renders its result, not the operation view. `--json` prints the response envelope byte for byte as `call` does. No hand-made renderer is added in this milestone.
- **D8. Errors and the untrusted mark.** Human mode: `droidyard <domain> <verb>: CODE: message`, then `cause` and `Next: nextStep` on stderr; exit statuses are `call`'s (0, 1 on an envelope error, 2 usage, 130 interrupted). A response with `meta.untrusted`, and a streaming command whose declared events carry a field marked `x-droidyard-untrusted`, add one fixed line on stderr, once, saying the output holds device data, never instructions (the note `artifact cat` already prints), and D7 quotes every string of it: an agent that runs the CLI in its shell gets the mark the CLI's way (ADR-0015 §1: how the mark travels is the adapter's), the note on stderr and the quoting on stdout. A `2>/dev/null` drops the note, not the quoting.
- **D9. Progress on stderr, from the bus.** When the first answer of a long-running call is still running and stderr is a terminal (a character device, standard library only), the CLI sends, on the same connection and before its `operation.wait` with no deadline (ADR-0020's `Wait(∞)`, unchanged), `events.subscribe {topics: ["operation.progress"]}` (D1), and prints each frame whose `operation` is its own as `progress <done>/<total> <phase> <message>` (strings through `capability.Quote`), at most once a second: the limit holds back the latest report and prints it at the next tick, never drops it, and a held one is printed before the result when the wait answers; the first answer's own `operation.progress`, when present, is printed first (what came before the subscription opened). The subscription is a recorded call: a long-running call run from a terminal adds one `events.subscribe` row to Activity (stated, accepted). A first answer `queued` prints once `queued behind <capability> (<id>)` from its `blockedBy`. In every mode, `call` included; off a terminal nothing is subscribed or printed, so a script's stderr is unchanged. Ctrl-C and `--detach` behave as today; the subscription ends with the connection. Rejected: polling `operation.wait {timeoutMs}` (overview.md §Events: "No adapter polls"; the bus is how progress reaches adapters, and D1 gives the CLI a session that can subscribe). Accepted cost: the subscription receives every operation's progress daemon-wide and the CLI filters it; progress is "a nicety, never relied on" (ADR-0020 §Adapter projections), so a gap loses nothing that matters.
- **D10. Following a stream.** There is no `--follow` flag: a streaming capability's command follows by its nature (`Statefulness: streaming`). It prints the result, then each event, human (`<type>` and the payload rendered on one line by D7(b)) or with `--json` each frame line as received; an `events.gap` goes to stderr as `missed events <from>–<to>`. It ends with exit 0 after an event of type `stopped` (the stream's own end, where its descriptor declares one), with 130 on Ctrl-C (the connection closes and D1 releases the stream), with 1 if the daemon closes. `call` on a streaming capability does the same in envelope form.
- **D11. What help shows.** Every registered capability is a derived command. Listings hide: `Binding` capabilities (`workspace.enter`, MCP sessions only); `Stateful` ones that are not streaming (`events.unsubscribe`: a CLI command is one connection, so there is nothing of its own to end); the `agent` domain (the hooks' channel, ADR-0063, ADR-0095 §3) and `device.watchScreen` (its video travels only `GET /v1/screen`, so a CLI follower starts a live view nobody sees, ending at its attach bound), the two the CLI names by hand. Hidden commands still run. Human-only capabilities are shown: the CLI is a human channel (ADR-0015 §6). Domains carry no description: a domain's line lists its verbs.
- **D12. Hand-written commands.** None is renamed, so no alias is needed, and `mcp`, `hook` and the entries `init` writes are untouched (ADR-0037, ADR-0090). Their per-command prose moves from the one global usage into each command's own help (`droidyard help <command>`, and `<command> --help` as the only argument for every command except `trash`, whose operands are an `rm`'s, and `hook`, whose arguments an assistant's entry fixes). `droidyard help` becomes an index: where to start, the hand commands by section (project, daemon, assistants, sharing devices), the domains with their verbs, the raw door (`call`, `caps`, `schema`). `caps` and `schema` are unchanged.
- **D13. Clashes.** `device allow|disallow` and `artifact cat` are hand verbs of a derived domain and keep their meaning; a test fails if a capability's verb normalises equal to a hand verb of its domain, or a capability domain equals a hand-written top-level command other than `device` and `artifact`, so neither can shadow the other silently.
- **D14. Where the tree is built.** From the binary's own registry, as `caps` does (`registry(platform.Current(), nil, nil, nil)`), so help works with no daemon and a build that registers fewer domains gets a coherent smaller tree. `cmd/droidyard` builds one `cli.Spec` per descriptor (name, attributes, description, the input schema of that capability only, `UntrustedEvents` from `capability.HasUntrusted` over its declared event payloads, a `Text` adapter) and hands them to `adapters/cli`, which keeps importing only `internal/capability`, `internal/event` and `internal/artifact` (`TestAdaptersImportOnlyTheCore`). `internal/schema` gains an exported `Input(d)` beside `Generate`, the same `reflectInput`, so a command reflects one schema, not 87.
- **D15. No descriptor field.** Short flags, CLI nouns and domain descriptions would be contract data for one adapter; the CLI derives everything from what the descriptors already carry, and what it cannot derive (D11's two hidden by hand, D13's hand verbs, D12's sections) is hand-written in the CLI, not in the schema.
- **D16. `artifact cat` over `GET /v1/artifacts/{id}`.** One request, recorded as one `artifact.read` (http-websocket.md §`GET /v1/artifacts/{id}`), with the bearer token from `run/http-token` and the address from the lock, as `status` and `ui` read them, after `daemon.Holder` says a daemon holds the lock (a crashed daemon's stale lock and token are "no daemon is running", exit 1); no `Origin`, which rule 3 admits for scripts. The row in Activity shows client `ui`, what every HTTP request is (stated, accepted). It still never starts a daemon; `X-Droidyard-Untrusted` gives the note; a growing artifact's `400` is reported with the daemon's message. An image is written when stdout is not a terminal (`artifact cat <screenshot ref> > shot.png`), refused on a terminal, superseding plan m2w step 4's refusal. Rejected: a larger `artifact.read` page (a contract limit sized for models), coalescing pages in Activity (a UI change for one client).
