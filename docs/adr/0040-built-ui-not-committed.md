# ADR-0040: The built UI is not committed; Go never needs Node

- Status: Accepted
- Date: 2026-10-09
- Relates to: ADR-0006, ADR-0039 §1, §3; plan m2a Q1
- Delegated: the main session, under the owner's standing instruction to apply the
  recommended option (plan m2a, reviewed in two rounds).

## Context

ADR-0006 has the core serve the UI's built static assets and ADR-0039 has Vite build them
from `web/`. Neither says whether the build output is committed, nor whether a Go build
needs Node. The Go side (`go build ./...`, `go vet ./...`, `go test ./...`, the pre-commit
hook on a Go-only change) runs today with no JavaScript toolchain, and most milestones
touch only Go.

## Decision

1. The built UI is **not committed**. `web/dist/app/` is git-ignored; the Go package `web`
   embeds `web/dist` over a committed `web/dist/.keep`, and `web.Assets()` returns the
   built app when it holds `index.html`, else nil.
2. A daemon built without `pnpm -C web build` serves a placeholder page at `/` naming that
   command and a rebuild. Every other route is unchanged.
3. `go build`, `go vet` and `go test` never need Node. The pre-commit hook needs pnpm and
   `web/node_modules` only when a commit stages a path under `web/`, the schema
   (`schema/capabilities.json`) or the hook itself.
4. The TypeScript client (`web/src/lib/api/capabilities.gen.ts`) is generated by every
   frontend `check` and `build` and is not committed either.

## Consequences

- A clone builds and tests on the Go side with no Node; the UI appears once
  `pnpm -C web install --frozen-lockfile && pnpm -C web build` has run before `go build`.
- A binary carries whatever UI was built when it was compiled; nothing checks that the
  embedded build matches the source. Release packaging, when it exists, must build the
  UI first.
- Diffs stay free of minified output.
- Documents to change: `AGENTS.md` §Build and test (the frontend commands), in plan m2a
  step 1.

## Alternatives considered

- **Commit `web/dist/`**: every `go build` carries the UI, but each frontend change adds
  minified diffs and needs a check that the committed build matches the source. Wins once
  binaries ship without a release build that runs Vite.
- **Build in the hook or through `go generate`**: Node on every Go change and in every
  `go test`, against ADR-0039 §3's "when a commit touches the frontend".
- **A build tag that embeds the UI**: the default binary lacks the UI, and forgetting the
  tag fails silently; the placeholder says the same thing at run time without a tag.
